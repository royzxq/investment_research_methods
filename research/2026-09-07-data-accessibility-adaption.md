# v2.22 有限数据调研方法改进

- 日期：2026-09-07。
- 类型：用户授权的定向方法改进；不是新一轮市场调研。
- 原版本：v2.21；新版本：v2.22；数据脚本：v1.10。
- 分支：`codex/accessible-futures-research`。本记录不表示已推送、合并或同步云端项目设置。

## 1. 要解决的问题

用户可持续取得的数据有限。旧流程要求港库、利润、开工、船流、战争险等全链齐备，又将模型缺项扩为整个品种/全池不可执行；报告还误用往年数据、D8豁免、期限参考值和账户空值。单纯增加“来源校验”会改善准确性，但不足以解决方法与数据能力错配。

本次目标是让研究能用现有行情与少量合适公开证据形成具体方案，再由真正必要的账户/执行条件决定能否执行。不是以少数据证明风险更小，也不设最低交易频率。

## 2. 实质方法变更

| 问题 | 新方法 | 边界 |
|---|---|---|
| 专业数据全量必填 | 执行必需、模型最低研究数据、可选增强三层；每候选先找一项独立公开产业事实 | 不能把行情或仓单冒充缺失的真实库存/船流 |
| 默认周度至少3条微观验证 | public_data要求价格/结构确认＋至少1项独立产业事实 | 事件、产能退出、地缘fade的强因果专属门不被替代 |
| MA所有结构等待海峡定量证真 | 区分独立domestic_public回归与geopolitical_fade | 国内模型须说明即使海峡未缓和为何仍收敛；仍核事件/双腿/压力，不解除方向性空头限制 |
| RB月差强制铁水等全链 | D14绑定实际依赖的收缩/成本因子 | 已知相关反证不能因指标可选而忽略 |
| 评分未定义分母 | 所有池按完整固定原始权重归一化；A分母90、D95、F90 | 不按当周有数据项动态重加权；不改变仓位系数公式 |
| A缺少可复算评分锚 | 明确D1–D5取值，D9无可信增量用3分中性配置 | 必要证据/计划缺失仍null；中性默认不冒充事实 |
| 少1天历史样本即缺项 | 3年各±20交易日，每年至少33/41个有效唯一同对样本 | 不补缺、不减少年份；33/41是治理下限，非统计显著保证 |
| 参考持有期/重建观察期无限阻断 | 事先定义具体计划，优先5–20交易日；新合约对可以回溯历史重建 | 不缩短已定计划凑手数，不继承旧合约许可 |
| gap_ratio无公式 | 明确压力止损损失/计划止损损失，披露场景与费用口径 | 减手数不改变比率；原阈值尚需新口径影子复评 |
| 永远待补的模型 | available/temporary_gap/research_only；连续两轮专业缺口复评可得性 | 排除范围与原已知阻断保留，不能用缩分母伪装覆盖完整 |

这是对验证门、证据路线和评分尺度的实质调整，**不能声称与v2.21完全等价，也不能把旧版记录当作新版历史业绩**。未扩大C趋势白名单、continuation、黄金或池外品种许可。

低敞口组合风险上限仍为 `min(实际净值×3.5%, 5000元)`，持仓与挂单共同占用；账户未知时最终手数为null。`futures_risk.py`的真实风险、单位与预算校验未改。

## 3. 调研方法与落地文件

- `framework/futures_framework.md`：0D当前协议、适用门、#5/#13/#26/#30、A评分/样本、MA/RB卡、gap定义、无历史预填的报告正文模板。
- `framework/FUTURES_DATA_PROTOCOL.md`：来源菜单、时效/年份/比较口径、公开替代边界、有限检索、候选流程和最小周报。
- 三个 `projects/*future*/INSTRUCTIONS.md` 与四个期货流程包装：先数据可得性，再研究；错误修复与市场变化分开，研究方负责具体方案，不反复把专业数据缺项交回用户裁量。
- `EXECUTION_AUDIT_TEMPLATE.md`：schema 2 JSON，把适用检查、已知否决、未知项、数据可得性和证据来源分开。

## 4. 数据脚本与报告校验

数据脚本v1.10保存原始settle/close/open与price_basis。SC护栏只用两端原始有效结算；缺失为unknown，不能用收盘或更早有效结算补齐。周涨锚定最新已完成行情日减7自然日，调研日9/7而行情日9/4时比较8/28→9/4。固定合约对输出1/5/10交易日价差变化，缺窗口/口径不一致/换月混对不生成变化。

报告校验器只检查JSON结构、状态与门集合、未知账户、日期内部一致性；不访问网络、不保证来源真伪、不验证完整经济逻辑、不授交易许可。运行命令：

```sh
python3 scripts/validate_futures_audit.py --input research/<date>-execution-audit.md
python3 -m unittest discover -s tests -v
```

脚本仍使用用户已有Tushare权限，本次没有新增无Token的CSV导入器；研究方可直接读取用户终端导出作为独立材料。未联网重跑行情，未用历史`1.txt`冒充本次输出，也未取得新的实际账户快照。

## 5. 下一轮运行方式与验收

1. 使用v2.22 canonical、数据协议和v1.10行情输出；先确认数据截至日期和SC专用列。
2. 只对MA/RB及真正激活的备选研究；每候选先交代具体模型、独立公开证据和相关反证。
3. 输出至多两份具体计划；无法完成时说明真正缺项，不再整包写“等待用户裁定”。
4. 有当期账户/执行材料后再算最终容量；发布报告前运行结构校验或披露未运行。
5. 连续记录8–10周前瞻影子样本，按独立机会去重，同时记盈利与亏损、成本、失效和数据可得性；不根据少量样本立即放宽阈值。评分锚、33/41样本下限和gap新口径均是待验证的治理选择，未证明提高收益。
