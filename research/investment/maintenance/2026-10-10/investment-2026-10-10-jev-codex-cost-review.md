# Jev 复评：以 Codex 用量及两端成本为目标

2026-10-10，Asia/Shanghai；生成端 Codex。承接[上一轮接入测试](investment-2026-10-10-jev-integration-benchmark.md)。本次纠正收益口径，并补测排序回传、原文核验和失败后的恢复。没有重跑完整公司投研，也没有变更 canonical/compact、模型设置或交易规则。

**结论：跨模型 token 总和不适合作为用户目标的判断标准。Jev 的外部金额开销很低，也能替代独立的 Codex 分流步骤；但在这批材料上，它没有胜过“普通程序定位后，Codex 只核验一次”的省量基线。完整核验对照的 Codex token 差异只有 −0.30% / +0.01%，最终主题索引各少标一项关联，不能验收为“质量不劣化且稳定省量”。维持按需排序/定位，优先消除重复分析。**

## 1. 计量边界

核心指标是 Codex 输入、其中缓存输入、输出；不把 Jev token 加到 Codex token 后判断是否节省。输入总量已经包含缓存输入，reasoning 是输出的组成部分，不再次相加。

本轮构造两个真实 Codex 消费端：

- **普通程序基线**：确定性关键词排序 → Codex 阅读原文并生成证据地图。
- **Jev 组**：同一候选的 Jev 排序 → 程序回传完整 ID 队列、覆盖缺口、主题不确定项和服务错误 → Codex 阅读同一批原文、处理回退并生成同样格式的证据地图。

两组都不按分数删除材料。排序回传经过程序压缩，不打印带全量正文的审计 JSON。公告使用 168 条标题和本地已有的全部 16 份公告正文（55,623 字符）；财报使用上一轮冻结的 53 页（51,505 字符），包含金标所需 41 页及 12 个固定抽样页。金标、旧投资结论及预期答案未进入提示。原文范围与哈希由普通程序核验，两组一致。

本轮消费端真实调用 Codex；Jev 标签复放此前相同材料的真实调用结果。**费用和串行耗时仍计入一次 Jev 冷调用**，不把实验复放当成生产免费缓存。Jev 计量分别是成功项目输入 140,571 / 93,427 token，耗时 90.465 / 35.141 秒。公告保留真实失败 A13、A122、A140；各主题回退项（含服务错误）分别为 43/27/128 项，财报为 2/3/0 项。没有重新调用 Jev 或重试这些错误。

这是一项受控消费端测试。首次完整框架阅读、网页发现、下载、PDF 视觉复核、估值及完整研报撰写未包含在这两个局部任务中；逐项 `show`、更多代理交接和分散原文读取若在实际研究中发生，仍须额外计量。因此下面的比例不是完整 stock-research 或本聊天的节省比例。

Jev 准备/MCP 调用的主聊天调度、工具说明首次加载等用量无法从这些 CLI 日志单独归属，没有填成零；表中 Jev 侧 Codex 用量只覆盖消费端，是完整主模型开销的下界。财报集合有意富集关键页，不代表整本 580 页或其他公司的自然候选分布。

## 2. 补齐原文后的真实 Codex 用量

第一次工具传输出现截断，处理过程和费用见第 4 节。为完成同范围核验，恢复阶段由程序将同一批完整原文逐字装载到新请求输入，避免工具显示截断；两组均重新核验，没有继承前次结论。这四次成功恢复请求，提供了完整原文的一次核验成本对照。

|完整原文的一次核验|Codex 输入|其中缓存输入|Codex 输出|输入＋输出|消费端耗时|
|---|---:|---:|---:|---:|---:|
|公告：普通程序|74,353|0|6,558|80,911|123.06 秒|
|公告：Jev 排序后|75,007|0|5,661|80,668|108.68 秒|

排序及回退信息没有消失在统计之外：公告组总输入增加 654，财报组增加 57。公告总 token 少 243，来自本次输出短了 897；财报总 token 多 7。输出篇幅有随机性，公告 Jev 答案的引句也比对照少，不能将这一点视作稳定、等质量的节省。

财报普通程序组命中 13,312 个缓存输入，Jev 组为 0；这会影响费用，但一次样本不能证明 Jev 必然降低缓存命中。没有为了消除这项波动继续消耗 token 重跑，保留实测值，并在费用解释中区分缓存情景。

若新研究需要先冷调用 Jev，再让 Codex 核验，分项串行耗时为公告 **199.15 秒**、财报 **145.23 秒**，对照一次核验的 123.06 / 105.97 秒。它们是两个实测阶段相加，不是同一次端到端秒表结果，也没有假定可以与必要前置调用重叠。

## 3. 为什么替代旧分流步骤仍然有主模型收益

上一轮隔离 Codex 分流步骤消耗公告 32,711、财报 60,384 个输入＋输出 token。把这些已实测步骤加到本次普通程序一次核验上，可核算一个“单独分流，再由新上下文核验”的分项基线：

|分项核算，非同次端到端|Codex 单独分流＋本次普通核验|Jev 后本次 Codex 核验|Codex 数量差额|
|---|---:|---:|---:|
|公告|113,622|80,668|少 32,954，约 29.0%|
|财报|125,280|64,903|少 60,377，约 48.2%|

这里已经保留原文核验，Jev 组也包含排序回传、不确定项与三个服务错误的处理；不是把原分流 token 全额当成净节省。不过旧分流和新核验来自独立运行、任务输出不同，没有测量共享会话下分流上下文如何延续及缓存，也没有补入旧分流答案的额外交接。这只是可转移主模型负担的分项账，**不是 29%/48% 全流程收益或质量验收结果**。

普通程序加一次核验本身就能去掉独立分流的重复分析，且不支付 Jev 费用。当前材料应先采用这个基线。Jev 只有在大量候选确实需要额外语义定位、且它能减少 Codex 原本必要的扫描/推理工作时，才有进一步收益空间；排序本身不解除原文、反证和附注阅读义务。

## 4. 失败回退没有按零成本处理

首次四次 Codex 请求各执行三个批量原文读取命令。`events.jsonl` 中的原始 `aggregated_output` 与源文逐字一致，但消费者报告工具显示被截断：公告涉及长员工持股计划正文；财报涉及中国移动受限存款及恒瑞风险页附近。**结束标记和落盘日志完整均不足以证明模型看到了完整正文。** 原试验提示限定只能各读一次，因此不能现场补段；这是本轮测试夹具的限制，不能当成生产推荐。

四次都保留了缺口。随后做四次完整原文恢复，所有第一次请求的消耗仍保留。失败尝试加恢复的实际 Codex 分项如下：

|---|---:|---:|---:|
|公告：Codex 输入＋输出|280,689|283,204|增加 0.90%|

三个真实 Jev 服务错误在两次公告消费尝试中均逐项复核了标题，并明确其正文在本地样本中缺失，没有把错误转为 no 或已验证。这里计入的是已发生的回退；没有假造缺失正文的获取和核验成本。

整批 Jev 中断、认证失败、超时后的不同恢复路径未实测；失败请求的提供商计费也未取得。它们保持未知，没有代入零，也没有用这一个样本的失败比例预测平均生产成本。实际生产应先缩小工具返回分段再补读；本轮完整重读是可审计的恢复成本实例，不是建议每次失败都重新读全集。

## 5. 两端金额：实测用量与账单分开

只读检查确认本机 `codex login status` 为 **ChatGPT 登录**。当前配置为 `gpt-6.1-sol`、low、`service_tier=priority`，没有改设置。完成事件未报告实际模型/服务档位，所以配置不被升级为提供商确认值；历史分流的实际模型也不回填。

CLI 没有返回单次订阅额度扣减、credits 扣费或美元账单。**真实逐次现金/credits 扣费均为未知，不能宣称已经省下某笔美元。** OpenAI 将订阅包含用量与 API 价格区分，并给出 credits 费率；本机配置若按 Fast 生效，credits 估算使用 Standard 的 2 倍，而不是把订阅包含用量的倍数当成现金单价。[OpenAI 定价说明](https://learn.chatgpt.com/docs/pricing)

以下仅是按当前配置模型、Fast、短上下文费率及**实际观测缓存**计算的条件估算：Codex API 等价单价为每百万输入/缓存输入/输出 $4 / $0.20 / $20；credits 单价为 100 / 5 / 500。缓存写入本轮报告为 0。[OpenAI API 定价](https://developers.openai.com/api/docs/pricing)

Jev 1.13 官方价格为每百万输入 $0.042，输出免费；按响应的成功项 usage，公告约 **$0.005904**、财报约 **$0.003924**，合计 **$0.009828**。这同样不是发票金额：折扣、账户免费额度、税费、失败是否收费未确认。上一轮全量 168 标题＋580 页成功输入 1,157,687 token 的公价约 $0.048623，也不宜仅因绝对金额低而默认全扫。[TypeSafe 模型与价格](https://docs.typesafe.ai/models)

恢复答案的来源引句检查：公告普通程序 38 条（35 条逐字一致，3 条仅空白归一后匹配）、公告 Jev 24 条全部逐字一致；财报分别 34/35 条全部逐字一致。这证明引句可回到本地文本，不证明所有解释正确。抽核两组对现金限制、许可收款与收入时点、局部否认的主要处理，仍须保留 PDF 表格、乱码正文、缺失正文及版本边界的缺口；没有据此宣称完整投研质量等价。

因此不把本次微小总量差异或第 3 节分项节省作为不劣化验收通过，也不放行 Top-K、只读 yes、低分免读或降低框架要求。当前决定为：

1. 公告标题优先普通程序去重、规则分类和一次原文核验；Jev 只用于确有语义歧义的大量候选。
2. 财报先用目录、关键词和结构关系定位；需要语义扩展时才用 Jev，对附注/主体依赖继续由 Codex 独立闭合。
3. 已把技能的收益判据改成 Codex 净用量，另列 Jev 费用，比较一次核验基线；明确算上回传、补读、缓存及失败，未改投资框架或现有模型设置。
