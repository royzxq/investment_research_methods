# DSH 首批接入：复盘与提交前审查

日期：2026-11-03，北京时间。范围为本次新增代码、生产 profile、依赖锁、对照驱动、测试和研究证据；未修改股票方法及共同验收逻辑。

## 复盘

首次实施对配置冻结、依赖版本和共同验收做了验证，但对取证质量的检查不够深入。最明显的问题是把 HTTP 返回了非空内容当成正文取得，把回归全绿当成新增日志格式已被覆盖。这两类结论都超出了当时证据。

复审继续读取保存的原始响应、已安装 DSH 的原生协议实现和异常路径，没有为改进统计而重跑收费模型。Search 来源覆盖、延迟比较和 AKTools 的 8 项财务抽查仍成立；Fetch 对照的解释需要纠正。当前接入选择保持 Search API + HTTP + 按需 AKTools，但原 HTTP 的取页缺口不能被返回成功掩盖。

## 已修复发现

| 优先级 | 发现与实际影响 | 处理及验证 |
|---|---|---|
| P1 | 原 HTTP 六次非空 200 响应全部在 100,000 字符截断；剔除脚本等后仅余标题/导航，不能支撑“原路径更有效”或“无需浏览器” | 纠正实施报告、ADR 和证据摘要。20 个原 Fetch 响应逐一复查：原路径实质正文 0/10，API 汇率页 2/10；不据有限覆盖全局切换。浏览器仍未测试，完整下载/按需补证仍必要 |
| P2 | usage 回退读取了简化的 flat chunk；真实 DSH v4 使用 `record.chunk.usage`，可能漏计流内实报用量 | 按原生协议修复，覆盖 attempt、缺直接 usage 的 message、最后样本和直接值优先级。32 个历史尝试重算，汇总与原统计一致：历史四条缺 usage 记录自身也没有嵌套 usage，未补造数字 |
| P2 | 一次压缩的 start/summary/end 会累计成多次压缩 | 改为成功 end 计一次，失败/未结束分开；真实生命周期结构的成功、失败和中断测试通过。历史样本无压缩，原统计无变化 |
| P2 | Web 驱动会将非抛出的 HTTP 错误页面/空结果记为成功；MCP 驱动未严格检查初始化/工具发现回包 | 明确非空 2xx 的传输成功口径，正文另审；增加 manifest 路径/重复 ID 检查，验证 MCP 初始化和所需工具，拒绝错误/无效回包。服务器失败后终止并关闭管道；驱动和输入留副本/哈希 |

另修正日志遇到非法 type/turn/step 时整次统计丢失的问题：保留该事件缺口并继续统计其他有效记录。统计失败仍是旁路观察异常，不能改变研究验收。

## 验证结果

- 宿主完整离线回归：**1,312 项通过，268.616 秒**。包含现有共享证据、回执、失败恢复及新异常路径；这些是离线合同验证。
- Node 对照驱动边界：**3 项通过**，验证 HTTP 错误/空正文、HTML 响应、案例路径、重复 ID 和无效输入。没有新增网络请求。
- 重算 32 个历史尝试：成功/失败/重试、工具、usage 和辅助搜索汇总均与原统计一致。44 个原 Web 调用按收紧的传输口径复核，传输统计未变；正文质量解释单独纠正。
- 原来的真实 Search/Fetch/AKTools 和 DSH 集成测试记录保留，不把离线重审称为新 API 实测；没有新增完整个股研究 A/B，也不声称整篇研究提速或实际账单降低。
- 原股票 canonical/compact 和共同验收代码未修改；生产配置 SHA 与首轮启用记录一致，旧冻结批次保持原工具选择。

首次接入的 1,306 项回归记录是当时版本结果，保留原件。本轮复审结果另存 `evidence/dsh-plugin-review-validation.json`。API 响应和历史 session 继续本地保存，必要的来源索引、审计笔记、摘要和哈希随本次提交保存。

## 保留边界

AKTools 抽查范围不代表全部财务字段正确；港股币种缺失仍须查公告。依赖缺失或漂移时预检会拒绝加载未测试版本，应修复固定环境或为新批次选择旧 profile。Fetch 的两次汇率正文说明定向补充价值，不能推出通用替换或所有页面失败；现有 HTTP 截断缺口也尚未通过浏览器测试解决。

后续评估应分别记录传输、正文、事实口径和最终研究交付，测试样本要来自真实协议结构。本次将这些经验保留为实现审查记录，不新增投资规则或放宽验收。
