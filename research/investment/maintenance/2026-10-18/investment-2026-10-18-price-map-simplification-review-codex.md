# 股票价格地图简化的定向审议

研究日：2026-10-18，Asia/Shanghai。生成端：codex。状态：方法提案，未采纳。范围：评估 P1/P2/T1/T2 的信息价值、歧义与维护成本；未修改框架、研究接口或交易系统。

用户关于“主要使用 P1/T1，P2/T2 的边际价值可能不足”的判断有较强依据。更明确的问题是 P2 在研究端表示第二档买入参考，在下游决策代码中又兼作止损锚；同一价格承载了不同的经济含义。建议研究交付以 P1、T1 为核心价格，将 P2 的分批执行功能与风险锚功能分开审议，将 T2 的逻辑失效与退出条件保留为独立条件。这里支持的是减少强制报价和语义混用，尚不能断言删减后收益更高或研究用时会下降多少。

## 现行规则与实际使用

| 对象 | 本仓现行含义 | 独立信息及主要问题 |
|---|---|---|
| P1 | V50 叠加基础折扣及风险折扣后的买入参考价 | 综合估值与安全边际，是核心输出；价格存在不等于允许买入 |
| P2 | P1 下沿再下调 5%–10%；对应第二档 40%，P1 对应 60% | 数值由 P1 派生，独立估值信息有限；另有取消、暂停、恢复及跨端消费状态 |
| T1 | 接近 V50 上沿，以及兑现、可达性、拥挤等变化时的第一层复核条件 | 可作为卖出评估起点；不是保证实现的目标，也不等于必须一次卖完 |
| T2 | 明显高于 V50，或盈利/现金流假设证伪、终局不可达等严重情形 | 合并了“涨得太贵”和“逻辑失效”两类原因；风险事件价值高，独立第二个金额的必要性较弱 |

依据：[canonical §6.1–6.5](../../../../framework/investment_framework.md)、[个股报价输出契约](../../../../.agents/skills/stock-research/references/valuation-and-output.md)。canonical 没有规定 P2 是止损价，也没有规定 T2 必须按固定涨幅算出一个金额；接口允许 T2 写价格条件与事件条件。因此，“四个独立价格都要精算”并非现行规则的准确描述。

### P2 的歧义确实存在于系统之间

定向读取相邻 `ai_investment` 仓库发现：

- [price_consensus.py:180](/Users/xinquanzhou/Workspace/ai_investment/src/analysis/price_consensus.py:180) 明确注明 P2 兼任止损锚，并说明调低/调高 P2 会产生不同方向的后果。
- [price_metrics.py:39](/Users/xinquanzhou/Workspace/ai_investment/src/technical/price_metrics.py:39) 将 `(现价−adding_price)/现价` 作为 `expected_downside_pct`，用于计算风报比。
- [decision_core.py:503](/Users/xinquanzhou/Workspace/ai_investment/src/decision/decision_core.py:503) 在价格触及或跌破 P2 时，将买入信号降档为轻仓试探；[同文件:545](/Users/xinquanzhou/Workspace/ai_investment/src/decision/decision_core.py:545) 又将 adding_price 用于止损距离及风险单元计算。
- [price_consensus.py:536](/Users/xinquanzhou/Workspace/ai_investment/src/analysis/price_consensus.py:536) 在 P2 多数拒绝且无报价的特定分支，会由 P1 和最小间距派生 P2。该数值是下游共识机制的产物，不是研究者重新给出的估值结论。

这些是静态代码事实，不代表已经核实真实交易触发或账户损益。尤其是已读“止损击穿守卫”的动作是买入降档，不能将它描述成“股价一到 P2 就自动卖出”。不过，P2 同时承载加仓和止损锚的语义已能确认，用户的困扰有具体来源。

**经济含义上的关键区别**：第二档买入价表示“在假设仍成立且允许增加暴露时，更便宜的买点”；止损锚表示“持仓风险达到某个限制时，停止承担或降低暴露”。两者可以在不同策略、不同状态中存在，但需要清楚分开。同一个折价系数不能同时证明“值得加仓”和“损失可以在这里止住”。

例如，仅用于说明：P1 下沿为 80、P2 为 72。价格跌到 72，若盈利与现金流假设仍成立，可能更有吸引力；若坏账、债务或盈利事实已推翻原假设，旧 P1 和 P2 都应重估或撤回。决定动作的是新事实、买入资格和仓位约束，72 本身不能回答这个问题。

实际止损订单也不构成保证损失边界：FINRA 的说明指出，波动可能短暂触发止损，成交价也可能明显偏离触发价。这仅用于说明价格锚与风险上限不同，不将美国订单制度外推为 A/H 市场具体执行规则。[FINRA，2025-03-26](https://www.finra.org/investors/insights/stop-orders-factors-consider-during-volatile-markets)

## P2 与 T2 的收益和成本

### P2 的价值更多来自分批纪律

保留 P2 的合理理由包括：预先安排第二笔资金、降低一次买入的时点依赖、在波动中约束临时改变计划。这些功能在稳定经营、估值置信度较高、实际采取分批买入且明确限制总仓位时可能有价值。因此不能因为近期未用到就宣称它长期无用。

但 P2 并非新估值。决定其金额的是 P1 下沿与 5%–10% 的步长，工作量主要是选择步长、解释选择、裁定取消还是暂停、定义恢复条件，以及报告和下游保持一致。少一次乘法几乎不节约研究时间；减少这些重复判断和语义争议才是实际收益。

当前 v3 还允许 P1 只有单一基准价，没有 low/high。此时导出器不能把 base 当 low 代算 P2。为了凑 P2 人为补一个 P1 下沿，会把输出格式要求反过来变成估值假设，应避免。

若 P1 已充分表达估值误差和风险，P2 再折价可能是有意的执行分批，也可能只是再次保守化；是否合理要看新增保护对应什么，而非“价格越低越安全”。Damodaran 对安全边际的讨论强调，额外保守有错失机会的代价，保守估值再叠加安全边际也可能重复计入风险。这支持检查边际价值，不足以直接否定本仓的 P2。[Damodaran，2016-05-03](https://aswathdamodaran.blogspot.com/2016/05/dcf-myth-31-margin-of-safety-tool-for.html)

### T2 的风险判断应保留，第二个金额未必必要

“明显高估”和“持有逻辑被证伪”都值得判断，但不适合统一理解成比 T1 更高的第二个卖出价。逻辑失效完全可能发生在股价低于 P1 时，不能等价格涨到 T2 才处理；反过来，价格达到原 T1 后若盈利及价值已上修，也不能仅凭旧目标价认定应该卖光。

保留独立 T2 数值的合理场景是确实需要分级减仓、且不同减仓区间有清楚估值依据。若用户从不依据第二档报价改变动作，强制产出这一金额的边际价值较低。现行 T2 原本已支持定性价格条件，因此这部分复杂度也可通过明确交付要求缓解，无需删除风险事件研究。

## 建议的简化方向

以下为待审议方法，不是已经生效的新规则。

| 项目 | 建议定位 | 必须保留的边界 |
|---|---|---|
| P1 | 核心研究报价，表达有安全边际的买入参考 | 标明估值日期、币种及用途；观察/冻结价格不授予买入资格 |
| T1 | 核心研究报价，表达减仓或卖出评估起点 | 必须明确对应的价值锚与假设；不保证到达，不默认到价清仓 |
| P2 数值 | 取消逐股研究的强制报价要求；确有分批计划时再由执行计划定义 | 不能悄悄把缺失字段填成止损锚；分批仍须总仓位约束及复评 |
| T2 数值 | 不再强制给第二个金额 | 严重高估仍可触发复核；盈利证伪、治理红线、现金链失效等条件完整保留 |
| 加仓、暂停、冻结与退出条件 | 独立表达，按对应风险作用于新增暴露或已有持仓 | 不能删掉 P2 后顺带删掉“禁止加仓”约束；临时禁止买入不等于强制清仓 |
| V50、V5、敏感性及监控 | 留在研究底稿与核心推理中 | 两个对外价格不代表只做两个点估值；坏情景与逻辑失效分析仍必要 |

对原 P1/P2=60%/40% 的处理必须明确：取消第二档报价不等于把原 40% 自动转给 P1。若未来修改，需要独立决定如何分批和限制仓位，不在本次分析中擅自放宽风险。

对下游依赖也不能以字段删除代替方法重审。当前 P2 进入风报比、止损距离、风险单元和买入降档；研究不再报 P2 时，应另行确定下游用什么可解释的风险依据，或者明确承认某个派生值只是执行参数，不能伪装成研究的估值结论。研究导出、共识计算和交易消费的兼容修改应作为一个完整范围处理。

## 反例与验证边界

支持简化的场景：用户只围绕 P1/T1 做决策；第二档从不改变实际执行；P2 长期仅机械派生；T2 只有重复的高估描述。此时删减强制报价能减少解释负担，并使逻辑失效更醒目。

保留可选档位的场景：用户确实采用两档限价买入或两档减仓，不同档位对应不同资金预算、价值情景和执行条件。取消这些可选档位可能削弱纪律、使决策更临时化，不能为了表面简洁强制单次建仓或清仓。

必须通过的边界：跌破旧 P2 但基本面未坏；低于 P1 但逻辑已证伪；高于旧 T1 但价值已上修；市场临时冻结但仍可估值；P1 无下沿；P2 取消后原 40% 如何处理；下游在 P2 缺失时如何计算风险。这些场景应能得到明确且彼此不矛盾的结论。

评估是否提高性价比，可以在同一批冻结输入上比较现行与简化输出：研究用时、返工次数、价格与状态矛盾、是否漏掉应有冻结或退出条件、两种输出是否真正导致不同动作。若要声称收益更好，仍需要另做不含未来信息、包含成本和真实可用日期的历史或前瞻验证。本次完成的是定义、代码依赖和产物统计核查，未做策略绩效回测或真实交易验证。

维护分类：`state_refresh=false`；`evidence_correction=false`（未改写历史产物）；`method_change=proposed`。建议优先审议 P2 双重语义和强制报价必要性；保留 P1/T1 核心输出与独立风险条件。框架、compact、脚本和历史报告均未修改。
