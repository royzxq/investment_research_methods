# 股票研究两价制及下游同步修改方案

日期：2026-10-18，Asia/Shanghai。生成端：codex。状态：待审方案，未实施。

本次目标已明确：核心价格只保留 P1 和 T1，加仓约束、逻辑失效及退出条件独立保留。建议按“方法与接口定义 → 两仓兼容读取与条件传递 → 两价决策候选验证 → 整包切换”实施。本次只制定方案，没有修改框架、技能、生产脚本、历史产物或交易数据。

前序依据：[价格地图简化审议](investment-2026-10-18-price-map-simplification-review-codex.md)。本方案是在该方向上的具体设计，不将建议写成已经生效的方法。此次属于 `method_change`；仅修改格式无法完成目标。

## 一、修改后的明确行为

| 对象 | 新定义 | 保留的边界 |
|---|---|---|
| P1 | 唯一买入估值参考，保留原估值与风险折扣公式 | 单价或确有依据的区间均可；不为格式补下沿；有数字不等于具备建仓或加仓资格 |
| T1 | 唯一价格型减仓或卖出评估起点 | 继续忠实提取报告金额或有效 V50 引用；不随意增加固定涨幅；不自动到价清仓 |
| 加仓约束 | 独立说明追加买入是否可继续评估、哪些限制有效、怎样解除 | 取消本轮追加计划、临时暂停、从严评估分别解释；股价下降不自动解除 |
| 逻辑失效 | 独立定义核心假设被证伪所需的事实及当前判定 | 不依赖价格是否达到 T1；证据未知不等于已经证伪 |
| 持仓处置 | 按证据分为复评、减仓评估、退出要求 | 临时禁止新增不等于清仓；研究退出要求不等于真实成交 |
| 仓位 | 保留 cap_final 和现有账户、组合约束 | 首轮保留“首笔 60%、预留 40%”的研究预算纪律，但解除其与 P1/P2 两个价位的绑定；预留部分需另作加仓复核 |
| V50、V5、敏感性 | 继续作为估值与风险分析底稿 | 可以保留内部机器审计值，前台核心报价只展示 P1/T1；不包装成新的第三个交易价格 |

本轮不取消固定首笔/预留预算比例，以免删 P2 顺带扩大首笔暴露。60/40 的分母是经 cap_final 约束后的本轮计划目标仓位，预留需扣除既有投入；不能每次触及 P1 都重新获得一笔 60%。若之后要取消该比例，应另列仓位方法变更。下游原本没有执行研究端 60/40 的模块，也不能借迁移直接套入一套新仓位算法；先核实际属主与现有约束，保持既有执行仓位上限。

研究报告中的 T1 非价格事件一并移入独立条件区，避免“订单已经恶化，但尚未到 T1 所以不处理”。不保留可选 P2/T2 报价、不改名为第二参考价、不由 P1 百分比再生成风险价格。

## 二、框架条款逐类迁移

| 旧条款 | 新条款处理 | 必须核对 |
|---|---|---|
| P2=P1_low×(1−step_down)，step 5%–10% | 删除公式、步长选择及相关报价验算 | 不把 P1.base 当 low，不换名称恢复折价档 |
| 保留完整 P1/P2、可保留 P2 | 保留 P1，并允许在全部适用条件满足时评估追加买入 | 仍需账户和组合预算，不等于必须加仓 |
| 取消 P2 | 本轮不安排追加买入；保留取消原因及重新研究条件 | 不永久禁止该公司、不自动卖出、不释放预留预算 |
| 暂停 P2 | 暂停追加买入，保留原窗口、适用对象、解除证据和逐股复评 | 日期过去或价格变低不能自动恢复 |
| P2 从严 | 加仓判断受该风险证据约束；逐股写清所需证据和当前裁决 | 不机械等同冻结；已有折扣、cap 调整继续保留；关键加仓证据不明则不追加暴露，另有entry约束才限制首笔 |
| 必要时取消 P2 | 保留“必要时”的裁量与论证，改为是否取消本轮追加计划 | 不能统一改为所有相关公司禁止加仓 |
| P1 60%、P2 40% | 独立首笔/预留预算 60/40 | 预算分批不再要求第二个价格；预留不自动投入 |
| T1 中盈利、订单、回款、拥挤、可达性等事件 | 移入独立复评/减仓条件 | 不要求先达到 T1，不统一升级为退出 |
| T2 中明显高于 V50 | 并入 T1 后的高估程度与持仓处置评估 | 不再要求第二个固定卖出金额 |
| T2 中核心盈利/现金流证伪、终局不可达 | 移入逻辑失效与相应持仓处置要求 | 保持原确认强度；不能因股价便宜继续按旧逻辑加仓 |
| T2 中宏观、油价、拥挤、Precheck 或双轴恶化 | 回查对应原规则，分别保留复评、暂停新增、减仓评估或退出要求 | 原动作为冻结的，不能全部改成清仓 |

重点迁移位置为 canonical §0、机制分类、Gate、§6.1–6.5、DCS 与 Price Map 输出模板；compact 同步。稳定 R1–R21、D1–D8 编号保留，未涉及的估值公式、阈值、AND/OR、例外与解除条件保持原义。

R6 的实质暴露、48h 窗口与过窗复核不变；R9 缺项不因报价非空消失；R21 退出仅回等待复核，仍不等于 D5 完整重建和逐股复评完成。D5 破线不自动否定存量硬证据持仓。方法兼容性冻结也必须阻断新增与追加，不能只写一句提醒。

需建立一张旧条款到新条件的迁移核对表，逐项标明触发、作用对象、动作、解除证据；不能只用文本替换删除 P2/T2。

## 三、调研输出与最小机器契约

### 新报价契约

建议新建 `stock-research/v4`，结构如下；字段名为本方案建议，尚未实现：

```text
meta                  原证券、日期、币种、生成端、报告来源
price_map             {mode, reason, v50, p1, t1}
research_controls     {entry, add, holding}
monitoring[]          独立条件及跟踪项目
```

- `p1` 沿用明确单价或实际区间协议；`t1` 新版只保留 `price_condition`。原 `t1.events`、`t2.events` 全部适用项逐条进入报告完整条件表，每条都有迁移去向；重点跟踪项进入 monitoring，当前生效或未知的控制进入 audit，不以删除字段丢失条件。
- v4 不允许 `p2`、`t2`，也不放两个恒为 null 的占位字段。旧 v2/v3 按旧协议读取。
- `v50` 是内部估值与 T1 引用核验所需，不是新增的核心交易报价；V5 仍留报告底稿。
- 新增的控制摘要只表达当前研究判断，不复制财务证据或整棵 Gate 树。详细依据仍在报告审计与 monitoring 中。

### 控制摘要

| 字段 | 状态 | 含义 |
|---|---|---|
| entry | eligible / blocked / unknown | 研究是否允许继续评估新建仓 |
| add | eligible / blocked / unknown | 研究是否允许继续评估追加买入 |
| holding | normal / review_required / invalidated / exit_required / unknown | 当前持仓逻辑与处置要求 |

每项附 `refs`，只引用本报告稳定约束/监控 ID；具体暂停、取消或从严的原因在被引用条目中保留。eligible 仍须通过账户、组合、价格与执行约束，不是下单许可。

entry/add 为 unknown 时不允许该类新增暴露，但不能因此停掉持仓检查或卖出通道。holding 未知只要求补证/复核，不能写成已失效或已经清仓。已确认 invalidated/exit_required 时 entry/add 都不得 eligible。仅需持仓复评不自动等于全面冻结；是否限制新增由对应条款单独判断。

报价用途与控制摘要必须一致：frozen/rejected 不得 entry/add eligible；unavailable 不得假定可新增；tracking/observation 的 entry/add 均不得 eligible。entry/add 任一为 eligible 均须 mode=buy_candidate；only-add 限制可以使 entry eligible、add blocked。这样的资格分离会改变旧下游“有 P1 数字即视为可继续买入”的行为，应明列为方法变化，并在切换前评估影响，不能称为纯格式升级。

### 独立条件与审计

monitoring 沿用现有 variable/current/as_of/trigger/action/source/next_check，仅增加 `id`、`kind`、`state`：

- kind 区分一般跟踪、建仓约束、加仓约束、逻辑失效、退出条件。
- state 区分 watching、triggered、cleared、unknown。待监测事件不是已触发限制。
- monitoring 仍为1–10个重点项目，按公司实际风险去重，不作为完整条件的唯一载体。完整适用条件表与全部有效阻断不受此展示上限限制；下游复核输入必须能取得绑定报告的完整条件表，而不只消费这10项或单个模型的摘要。

因为现有 `stock-research-audit/v1` 将所有 blocking 约束都禁止 buy_candidate，无法表达“首笔可评估、仅加仓被禁”，本方案建议新批次升级为 `stock-research-audit/v2`：

```text
constraints[] = {id, scope, status, action, reason, release_conditions, ...}
scope         = entry / add / holding 的适用集合
status        = blocking / unknown / clear / not_applicable
release_all_of = {entry:[ids], add:[ids], holding:[ids]}
```

action 承接原 freeze/eligibility/reject/unavailable，并明确 review_holding/invalidated/exit_required。freeze/reject/unavailable及已确认逻辑失效/退出要求作用于全部新增暴露，scope必须包含entry+add；仅加仓暂停使用scope=add的eligibility限制，不把整体mode升级为frozen。旧 constraints 的经济含义逐条迁移，不把改字段名当作完成。

只有作用于 entry 的约束影响首笔资格；only-add 不通过全局解除清单再次冻结 entry。每个 release_all_of 集合必须精确覆盖该范围所有未解 blocking/unknown 约束。D5.clearance、全部解除、风险唯一归属、折扣基线及 P1 算式检查继续保留。

控制相关 monitoring 的状态和研究控制摘要必须与同 ID 审计一致；普通经营观察无需强造 audit constraint。triggered对应blocking、unknown对应unknown、cleared对应clear且须解除证据；watching不进入release_all_of。机器不靠中文 action 文本猜测是否允许买入。正常状态可以无 refs，blocked/unknown/review_required/invalidated/exit_required 必须有可解析依据；合同缺失本身作为明确缺口，不用空列表冒充已解除。

`available_at` 继续由实际封口/原子发布属主写入，不由研究者按估值日零点倒填。它用于下游和回测判断控制结论何时可知，不表示条件何时首次发生。

## 四、下游系统同步方案

### 报价、资格和条件必须一起发布

现有 `research_consumer` 和 CSV 写入器会在 P2 缺失时派生或沿用 P2；这些新版分支必须移除。新契约缺 P2 的含义是“已退役”，不属于模型拒绝、报错或少数报价，不进入旧 P2 拒绝投票。

P1/T1 保留原共识计算、默认等权、模型席位、币种与精度规则。本次不修改模型权重，也不将研究条件做数值平均。

继续以 `investment_prediction.csv` 为下游业务唯一来源，建议随现有原子发布增加版本标记和一个 `research_controls` JSON 列，保存各 scope 当前状态、来源、引用及必要解除摘要；沿用现有 available_at。完整规则仍可从绑定报告追溯，日志仅供审计，不另建一份具有交易权威的状态台账。

具体合并纪律：

1. 保留所有成功研究来源中实际适用的控制依据；不能像当前 monitoring 文本那样只选一个模型，丢掉另一模型的有效限制。
2. 已确认的硬性约束不通过价格投票豁免。模型对限制是否成立有实质冲突时，将受影响 scope 标为 unknown、要求定向裁决；不能平均成允许，也不能仅因争议自动清仓。
3. 模型缺席不是拒绝。旧格式、人工报价没有控制资料时，不据数字补造 eligible；恢复需要明确的新证据和复评。
4. Coze 继续作为补充报价来源时，只提供 P1/T1 不会被视为否决票，也不能用缺失控制内容来解除主研究的限制；其明确新风险进入复核。
5. 正常报价与控制通过同一发布事务，不能先发布价格、稍后才写阻断。另保留明确的control-only原子发布路径：已验收的阻断/逻辑失效/退出要求，不能因T1缺价、报价冲突或提取失败而不生效。该路径只收紧控制，不凭不完整材料恢复买入；新记录不提供新报价，旧价格从历史记录解析并保留各自原日期，不复制到新估值行伪装刷新。控制本身未通过验收时才不得发布。
6. 跨轮次保留仍有效的限制。新来源缺席、未提旧规则、只给eligible或出现unknown，均不能清除上轮未解阻断；解除必须明确指向原约束ID及适用范围，并给出满足解除条件的新证据和复评。持仓处置有争议时记录待复核，不默默改为normal。该接续仍由CSV版本化控制及解析实现，不另设平行权威台账。

`research_eligibility` 扩展为按 entry/add 分流的最终检查。能可靠取得当前持仓时分别判定新建仓与追加；无法判断时不得靠“可能是首笔”绕过 add 限制。检查必须位于策略及 AR 等升级之后，并在执行/保存前复核。已有 P1=reject 历史路径继续兼容，独立 T1、持仓风险处置继续可用。

### 两价决策数学的推荐验证基线

这部分无法等价地删除字段，必须作为独立方法变化验证。推荐先实现下面这一套影子候选，不在验证前切到生产：

| 项目 | 推荐候选 | 验收重点 |
|---|---|---|
| 价格位置 | `x=(现价−P1)/(T1−P1)`，要求 T1>P1 | P1为0、T1为1；与旧 P1至T1区间一致，但两端尺度改变；不能沿用旧 x=−1 极度超跌或重仓阈值 |
| 买入资格 | P1价格条件、既有最低预期上行要求、独立 entry/add 控制、原体制及复核条件共同判断 | 价格越低不自动加大仓位；报价存在不自动放行 |
| 原 P2 风报比 | 退役 `(T1−现价)/(现价−P2)` 及依赖它的 guard/强收益升级 | 不把 ATR 比值继续命名为原 RR，不套旧 2.0/2.4 等阈值；删除保护会改变买入集合，必须披露 |
| 价格驱动升档 | 新版基线取消单凭低价或旧 RR 产生的重仓/强收益升级 | 不借删除 RR 直接恢复 BUY/HEAVY_BUY；其它技术、仓位策略按现有作用范围保留并逐路径验收 |
| 风险单元 | 复用已有波动率/ATR 备用路径：有效项中取 `min(1.65×σ20d, 3×ATR14/现价)` | 去掉 P2 止损距离，标为市场波动尺度；不宣称最大亏损或保证止损；不改 min/max 或参数 |
| 风险数据全缺 | 新增暴露转待复核/HOLD，已有持仓继续检查 | 不用 0/None 让风险上限静默失效；明确属于新候选的缺数处置 |
| AR修订分数 | 新候选为 `(ΔP1+ΔT1)/2`，Δ沿用原相对变动定义 | 与旧三价分数隔离；原阈值和升级效果重新验证，保留实际可用日期和T+1 |

统一 x 的上尾也不同于当前 `现价/T1`；下尾 x=−1 隐含 `现价=2P1−T1`，当 T1≥2P1 时甚至不对应正价格。因此 x 只提供位置/诊断，旧极端分位阈值和买卖档位映射不能原样搬入。若只为保留旧档位而倒算一个下界，就重新制造了 P2。

影子基线的价格候选动作明确如下，不由开发者自行补档：现价≤P1且既有最低预期上行条件通过时，价格侧最多形成普通BUY候选，之后仍过entry/add、体制、复核及仓位约束；P1<现价<T1时价格基线HOLD，不由原RR强收益分支升级买入；现价≥T1时进入既有卖出侧分级和后处理，继续使用其原卖出侧坐标/阈值，不将诊断x直接套进旧阈值。独立持仓风险条件在全部价格区间均可产生处置要求，技术降级及既有保护仍按其适用范围执行。

研究端“T1是评估起点”不等于本次改变执行端卖出算法：现有决策核在一些T1附近情形可能返回CLEAR，并有缓冲、52W等后处理。推荐基线明确保留该卖出侧行为，而不宣称T1触达永远只轻减；若要改成统一轻减或必须人工复核，应另列卖出方法变更。这项区别需在影子报告按卖出原因单列验证。

去掉正的 P2 距离项后，在其余有效分量存在时，新的 min 风险单元不会比原 min 更小；这只描述该计算的局部方向，不证明整个策略更安全。原风险单元在默认参数下也常不实际约束仓位，不能夸大其保护。回测和对照必须同时检查买入数量、升档、仓位与退出。

P1=T1、T1<P1或缺价时，研究原文不改价、不造间距。下游不计算上述坐标、不产生新增买入候选；若存在独立有效 T1 或持仓风险条件，仍可进入卖出/复核路径。

### 保留已有独立止损，禁止混用

当前 sell_agent 成本亏损纪律、成本不可用时的高点回撤处理，以及回测执行器的追踪止损都独立于研究 P2。本次分别保留其适用对象、现有参数、触发口径和持仓信息来源；不将回测追踪止损参数替换实盘成本止损，也不把其中某一条包装成新的研究价格。

卖出 agent 的价格区间改为 below_P1 / P1_to_T1 / above_T1，移除 below_P2 和距 P2 字段；精确等号归属在接口测试中固定：现价<P1、P1≤现价<T1、现价≥T1。此为展示区间，买入参考资格单独使用现价≤P1，两者不能混作同一枚举判断。缓存、日志和展示必须识别新契约。独立逻辑失效/退出要求进入持仓处置流程，不因 T1 未到、加仓被禁、研究报价缺失或旧缓存而消失。研究要求仍须保留证据、处置结论与执行边界，不能伪报成交。

## 六、历史、冻结批次和回滚

1. **历史原件不迁移覆盖。** 旧报告、JSON、报价原始记录、CSV旧行、封口与回执保留字节和哈希。历史回放按历史协议；新生产逻辑不使用旧P2补齐新行。
2. **旧未完成批次按冻结契约运行。** 新批次冻结 delivery_contract、prompt_template 和 audit版本。当前runner会用活跃提示词重建校验旧prompt，因此必须先建立版本路由。旧manifest缺标识时只能匹配可证明的旧模板，不改原prompt/input/hash；运行器还须按冻结契约选择旧交付附录/旧writer，不能让活跃v4技能或默认build覆盖旧交付要求。无法恢复完整旧运行契约则保留旧批次，显式重新准备。
3. **读写职责分开。** 新普通build只写v4；旧冻结批次经明确批次契约走旧writer。封口读取支持旧版，不把新交付格式门禁追溯应用于旧完成稿。
4. **latest按日期与正式配对选择。** 新schema不自动赢过较新日期的旧schema；生成端隔离、rN不自动提升、失败不覆盖的规则保持。历史latest可供阅读，缺新版控制信息不能据此推定生产准入。
5. **方法兼容性显式判断。** 退休P2/T2改变方法指纹，不能仅登记“兼容”就把旧冻结研究当作完成新方法复评。新adopted handoff必须在方法实际采纳后建立，旧记录不改。
6. **CSV过渡保留旧列但新行置空。** 这样保留历史读取能力；v4运行分支不再读取/推导adding_price。待历史读取接口收敛后，可另做存储清理，不能直接重写所有旧行。
7. **回滚按整包，已知风险事实不回滚。** 两仓代码、方法/契约和发布版本共同回滚。保存可恢复快照与事务记录，已发v4产物仍保留；旧代码不得把v4行当v3后自动补P2。切换后新确认的blocked/invalidated/exit_required必须继续经兼容控制入口生效，不能只恢复较早CSV或报价就重开买入。若旧版本无法承接当前控制，持续暂停新增并保留持仓处置，而非拼接旧P2与新P1/T1或回退风险认知。

历史读取分支有真实旧记录/冻结批次使用，不属于可直接删除的死代码。已被新实现替代且无历史用途的生产补价、旧P2投票和旧策略路径，则在切换后连同失效测试一起收敛，不长期保留双重生产语义。

## 八、必须通过的验收场景

| 场景 | 预期结果 |
|---|---|
| P1只有base，没有low | 正常两价交付，不补P1下沿、不产生P2 |
| v4输入含p2/t2 | 拒绝新交付；旧schema读取仍可通过旧协议 |
| frozen且P1/T1可估 | 价格保留，新增/追加受阻；不自动退出 |
| entry eligible、only-add blocking | 首笔资格不被错误冻结；追加买入不可被AR或升档绕过 |
| 跌破旧P2、核心逻辑仍成立 | 不因旧数字自动加仓、减仓或宣告失效 |
| 逻辑已确认失效、现价低于P1 | 禁止新增/追加，持仓处置按独立要求继续，不等T1 |
| 原T1弱化事件触发但未证伪 | 复评/减仓评估，不升级成自动清仓 |
| R21退出但未重建或未逐股复评 | 不恢复entry/add资格 |
| 多模型对加仓限制冲突 | 受影响scope unknown，保留全部来源；不平均成允许 |
| 人工两价、Coze两价、旧三价无控制摘要 | 报价可按版本归档；不凭缺失控制解除限制；模型缺席不作拒绝票 |
| P1=T1、倒挂、缺价或非有限值 | 不造价修复；新增候选不可计算时明确停止；有效独立T1/持仓风控仍运行 |
| T1/P1极高，统一坐标出现极端值 | 不照搬旧−1重仓阈值，不生成隐含第三价格 |
| σ或ATR单项缺失、全缺失 | 单项按候选定义计算；全缺失阻断新增，不能以0/None放行 |
| 原60/40预算取消第二档价格 | 预留资金不自动进入首笔，现有执行cap不扩大 |
| 旧prepared、旧audit-v1、旧seal | 按冻结版本恢复与原字节校验，不修改历史哈希 |
| 新T1但旧P1 | 各自价格日期保留，不刷新旧P1寿命或引入回测前视 |
| 新报价写入中途失败/重复调用 | 价格与控制均不部分发布；重试幂等，无P2再生 |
| 明确阻断/退出已验收，但T1缺失、歧义或倒挂 | control-only原子发布及时收紧；旧价格日期不变，不能保留旧eligible |
| 新轮次未提旧阻断或原来源缺席 | 旧有效限制接续；只有明确解除证据和裁决才清除 |
| 发布新退出要求后回滚代码/报价 | 新风险要求继续生效；无法兼容则暂停新增并保留持仓处置 |
| 暂停买入、缺研究价格、旧缓存 | 已持仓止损/逻辑失效复核与卖出通道不被屏蔽 |
| 历史与新版模型评价 | 两价/三价评分按版本分开，不因少评分项自动改变权重 |

研究仓应运行股票governance、离线unittest全套和被修改技能的quick_validate，另做人类语义保真抽检。下游先跑受影响的writeback/eligibility/consensus、price metrics/risk unit、AR、sell_agent和position_sizer定向测试，再执行无外发的真实本地路径验收及仓库规定的代码/设计审查。

影子对照至少记录：研究用时与返工、遗漏条件、买入候选数量、升档来源、追加次数、仓位、换手与费用、卖出原因、最大回撤，以及按实际available_at/T+1可用的收益。结构通过不证明投资方法有效；仅字段删除也不能证明节省了多少成本。
