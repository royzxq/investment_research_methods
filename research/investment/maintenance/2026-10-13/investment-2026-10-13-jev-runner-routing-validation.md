# Jev runner 注册、触发与调用记录验证

日期：2026-10-13（Asia/Shanghai）。本次修改位于主目录，基于 Git `24e7285`，尚未提交。

## 已接入的行为

Codex 和 Claude runner 均注册 `jev_research/research_jev_route`，原文由普通程序直接交给已安装的 Jev MCP，宿主仅接收候选 ID、字符范围、相关度概率和失败信息。Claude 的 strict MCP 配置包含包装工具；Codex 在本研究子进程关闭原始 Jev server，统一经过包装工具记录。全局 MCP 配置没有修改。

默认 `auto`，可用 `--jev-mode auto|off|force` 或 `RESEARCH_JEV_MODE` 选择；命令行优先，重试默认保留首次模式。程序对已提交的候选批次判定：公告至少 8 个候选或年报至少 6 个候选，且候选正文合计至少 12000 字符，未声明已有全部精确范围时调用。精确范围、小批次及正文少都有具体跳过原因。`off` 不注册工具，`force` 支持明确调用和连通性验证。

这些阈值是待校准的开销参数，不是投资框架规则，也不证明达到阈值就有净收益。每次最多 50 个候选、500000 字符，单段最多 200000 字符；超限明确拆批或回退，不截掉尾部。所有候选保留，分页复用同一结果，失败/不确定项继续核验。排序不会提高证据等级，金额、现金、主体、Gate 和估值仍须当前宿主主模型查原文。

本次执行的 `jev/calls.jsonl` 区分路由请求、阈值决定、后端启动、后端工具提交、结果、缓存续页和校验失败。保存实际候选来源哈希、提交条数、工具返回字节、耗时、已报告 usage、错误类型和回退状态；不保存密钥。最终 `jev/summary.json` 同时进入 `process.json.jev`。运行中的 CLI summary 只读查看，不提前冻结最终摘要。

`not_requested` 明确表示没有提交候选，不等于程序已评估后跳过。启动失败不计工具提交；`invoked` 仍要检查结果，工具提交本身不证明 TypeSafe API 成功。成功项 usage 与失败/在途未知用量分开，SDK 内部重试次数和货币费用不可得时保留 null。

真实 API 使用两条明确标注的合成公告（许可/条件付款与行政通知），`force` 仅用于小规模连通验证。没有提交私有持仓、账户或凭据；example.com URL 仅标注测试来源，不冒充公司披露。

该次调用：1 次 `jev_triage` MCP 提交、2 个候选项请求，后端报告 input=692、output=44 tokens；包装工具返回 1075 UTF-8 字节，路由耗时 2.065 秒；从模型发现、文件准备到最终摘要共 2.890 秒。Jev 通常按候选项发起请求，不能把 1 次 MCP 提交误当成仅 1 个底层推理请求。内部重试/失败费用未知，货币成本未测量。

本次没有重跑恒瑞端到端研究，没有测量 Codex/Claude 主模型 token 净收益，也没有证明所有关键投资证据的语义覆盖率。离线验证证明排序/错误/分页机制保留候选；完整投研仍须遵循已有原文核验契约。日常研究是否真正调用，现在可以根据本次日志区分未提交、阈值跳过、失败及成功，不要求每天为产生日志而强制调用 Jev。
