# 恒瑞材料 Claude Code 小范围端到端对照

日期：2026-10-12（Asia/Shanghai）。报告整理端：Codex；实际被测端：Claude Code 2.1.296。CLI 报告的模型标识为 `deepseek-flash[1m]`，两组都使用当前默认路由，未指定模型或 effort。不能据此认定底层模型提供方，也不能将结果外推为 Anthropic Claude 模型的收益。

**此次没有证明 Claude Code 的净节省。** 首轮“非缓存输入＋输出”只减少 **0.8%**，耗时反而增加 **16.4%**。计入相同范围的独立核验、优化组真实超时及恢复后，基线该项为 **82,329**，优化组至少 **84,342**，即至少增加 **2.4%**；累计 CLI 进程耗时为 **658.0 → 985.9 秒，增加 49.8%**。优化组超时阶段没有最终输出计量，故完整 token 总量未知，不能报告精确的整体节省比例。

最终两组通过本样本 **9 项关键语义检查**、16/16 个主题—证据对应关系和逐字引文检查。首轮并非无错误：基线遗漏 KIOMED 的“拟签订”限定，优化组将特许权发生额写成“所支付的对价”；追加核验修正了两项，开销没有扣除。两组首轮都保留了 BMS 净销售额分梯度提成及排除中国大陆、香港、澳门的地域限定。

### 超时阶段的计量缺口

Claude `input_tokens`、缓存创建输入、缓存读取输入是不同字段；总输入按三者相加，`modelUsage` 与 `usage` 不重复相加，估计的 thinking 进度不作实际用量。[字段语义依据 Claude 官方文档](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#tracking-cache-performance)。这里按当前路由返回的兼容字段计数，未取得网关账单或订阅额度扣减。

超时阶段无最终 `result.usage`。按唯一 assistant message ID 取最后一次输入计量，可追溯到已报告的非缓存输入 30,219、缓存读取 146,304、缓存创建 0。相同方法在此前三次正常完成运行中，三项输入均与最终事件完全相符。但 message 中的输出字段一直是 0，正常完成运行的最终输出却非零；因此这些 0 不能用来填超时输出，尚未报告的请求用量也保持未知。

最终表格只把这些已报告输入作为下限，另加所有成功阶段的最终用量。**即使完全不加入超时输出，优化组非缓存输入加输出也已超过基线。** 完整含缓存总量的下限不能冒充实际总量，不能从下限计算“节省 42%”之类比例。测试五次尝试合计至少处理 1,702,671 个输入加输出 token，非缓存输入加输出至少 166,671；实际未报告部分不填零。

## 证据质量

最终语义检查逐项核对：许可主体/拟签状态/附注联系；人民币发生额与现金收付；瑞宏迪现股东增资计划；否定披露范围；BMS 首付及周年组成；潜在总额和交割条件；13 个项目阶段；P166/P167 委托受托表头、单位及收益；净销售额分梯度提成与地域。两组 9/9 通过，最终逐字引文分别为 37/37、36/36。

基线原 limitations 中的“笔误/不一致”标题被独立回执指出为陈旧表述。最后程序仅据该回执与已修正 C1，将其规范为会议日和披露日，不修改事实条目或另增加模型轮次；保留原稿、修订稿及编辑差异。日期区别不构成已证实的原文错误。

这些结果不证明原 PDF 全文穷尽、来源真实性或已发生现金收付。A126 前两页乱码、未核原 PDF/更正版本、缺少付款及交割凭据、部分关联主体未逐名匹配等限制继续保留。没有以证据 ID 或引文匹配替代语义核验。

## 今日实际接入情况与判断

读取到的 2026-10-12 主 CLI 日志共有 11 次尝试：Claude 的 `research_reader.py` 命令 1 次、Codex 15 次；两端 ledger 调用和 `research_evidence.py` 调用均为 0，未出现 Jev 工具调用。这是主日志范围，子代理完整工具记录未必在其中；缺少脚本调用不证明没有手工复用，也不能据此推断所有公司都重复读了全文。

当前 Claude runner 命令明确使用 `--strict-mcp-config` 及空 `mcpServers`，该启动路径没有按需 Jev MCP 能力。未调用 Jev 与本次默认程序定位策略一致，不能将其直接解释为此次不省 token 的原因。

当前优化主要是共享技能指令与可选程序，并非执行器强制编排的去重流水线。今日日志不能证明这些机制已经系统落地，也没有为今日完整公司研究建立同材料、同模型、同义务的旧流程对照。此次恒瑞实测进一步表明，减少原文与工具调用不保证非缓存净用量或时间下降；核验、引文修正、格式交接和失败恢复可能吃掉收益。

因此目前不应宣称 Claude Code 已具有确定的 token 节省效果。下一步应先验证实际定位/合并接入、按宿主校准工具返回预算、减少确定性引用及交接处理的模型往返，并保证失败时能收回计量；保持关键事实核验后再复测。没有证据支持为了出现调用记录而强制启用 Jev。
