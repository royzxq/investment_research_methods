# DSH 网页、PDF、分页补证闭环与效果记录

日期：2026-11-08（Asia/Shanghai）｜生成端：Codex｜范围：用户授权的三类补证工程。

已实现并为后续新准备批次启用 `dsh-deepseek-flash-high-recovery-v1`。新 profile 在已有取数体检上增加有界补证、原件留存、按范围读取和采用记录；旧冻结批次沿原 profile 运行。没有改变投资方法、模型、排期、共享事实边界、研究成功验收或最终价格合同。

## 1. 实际行为

| 场景 | 实现 | 仍须研究者完成 |
|---|---|---|
| 原生网页返回显式截断或无可见正文 | 自动尝试同 URL 完整下载，保存原始字节及有定位的文本，避免同源重复补证 | 核主体、披露日期、正文范围与相关性；下载失败或动态页面仍需另找可核验入口 |
| 原生 PDF 取数失败，或直接调用公开 PDF URL | 下载并验证文件头，PyMuPDF 按页提取，保留 PDF 和页文本；按需渲染原页 | 空白/扫描、跨页表格、单位与负号继续核页；生成图片不代表已经看图，更不代表 OCR 正确 |
| AKTools 分页不足 | 保存已获页，从首个缺失偏移续补；自动一轮最多3页，之后可按 gap_id 继续，最多3轮 | 确认所需报告期、币种、单位及原公告；完整覆盖返回表不代表全历史或事实可信 |

分页仍采用真实的 offset/returned_rows/total_rows 口径。尾页的 truncated=true 不引起循环；总数漂移、页内容冲突或主体错误停止续补。网络或工具策略拒绝导致续补失败时，保留已有可靠片段和明确缺口。

其他工具策略继续有效。本机 DSH 的执行前拒绝也可能进入 post-execute；新插件单独确认原调用确实进入了获准的执行流程，避免被拒绝的 PDF 请求通过补证另取。补充分页及补证工具本身也走原生工具策略。原始返回值和错误身份不被改写；PTC 子调用继续收到补证提示。

## 2. 三阶段记录

1. **取得材料**：记录触发问题、尝试轮次、补充分页调用、下载尝试、耗时、完成/部分/冲突/失败/取消状态及原件哈希。
2. **读取材料**：关键词只定位；实际按页、文本范围或行范围返回的片段生成读取凭证，绑定原文件和片段哈希。
3. **声明用途**：研究者依据读取凭证记录采用、部分采用、未采用、未解决或拒绝，并说明相关输入、范围、理由及采用时的报告章节。

第三阶段明确是研究者判断。程序没有宣称独立核实事实，也没有检查最终正文是否确实引用；对应统计仍为 null。没有读取凭证不能凭空声明采用，读取了也不会自动标记采用。后续对同一凭证的否定可以替代早先采用声明。

运行证据位于每次尝试的 `evidence-recovery/<来源摘要>/`，按不可覆盖事件保存。已有 `runner/dsh-metrics.json` 增加可选 `evidence_recovery` 汇总，核对引用文件哈希，且不输出来源正文、URL、请求参数或评审理由。旧尝试没有新目录时不添加这部分指标。统计不参与放宽验收。

## 3. 版本与工程边界

新 profile 冻结补证插件和文档工作脚本，最终回执检查其哈希。继续使用现有固定 AKTools 环境和已验证的 PyMuPDF 解释器；没有安装依赖。原 `health-v1` profile 保留，可作为后续批次的回退选择。

文档下载仅支持公共 HTTP(S) 标准端口，固定已检查的 DNS 地址，逐次检查重定向并保留 TLS 主机名核验。单文件与提取文本上限各32 MiB，PDF最多1000页，工作进程90秒；超限、解析失败、压缩响应暂不支持等均显式留下缺口。取消会终止并回收工作进程。相同文档 URL 在一次尝试内不重复下载，参数相同的分页共享覆盖状态。

目前不自动安装浏览器、不做 OCR，也不拦截所有 bash/curl、本地 PDF 或其他 MCP 路径。要进入文档补证闭环，使用 `research_recover_evidence(url)`；原始来源、披露日期、单位、附注与语义完整性继续按原取证规范核验。
