日期：2026-10-10，Asia/Shanghai。生成端：Codex。范围：流程审计、官方资料调研与合成样本接通验证；未改动现行技能、框架、runner 或 Jev 配置，未重跑公司研究。

## 3. 哪些环节适合 Jev

Jev 接收文本与事先定义的问题，返回选项、概率或分值。当前官方模型页列出 Jev 1.13、文本输入、64k 总请求限制以及 state 加最长单题 32k 的限制；英文表现优先，中文需单独评测。它适合明确、重复的语义判断。[模型说明](https://docs.typesafe.ai/models)。

|环节与优先级|交给 Jev 的具体问题|交付给主代理的内容|边界|
|**优先：公告候选筛选与分流**|材料涉及业绩、回购、融资、收购、诉讼、担保、重述中的哪些主题；关联哪些 required_inputs|公告 ID、主题标签、待读优先级、低置信标记|先由代码检查主体、日期、分页与精确重复；必要财报和高风险公告直接保留，不能只凭标题判无风险|
|**优先：长文段落与附注定位**|哪段涉及受限资金、一次性利润、订单兑现、支付义务或股本变化；哪些段落支持或反对当前假设|原始文档 ID、页码、段落 ID、相关输入标签|命中后读取完整表格、相邻附注及跨页上下文；找不到不等于不存在|
|**第二批：复评增量分流**|新旧同口径片段是否重复、补充、改变条件、出现冲突或无法判断|需重开的证据/输入 ID、旧新位置|内容哈希去重先由代码做；行情及新披露仍按时效更新，不能用“没有新命中”证明无变化|
|**第二批：反证与矛盾预警**|片段是否否认已完成交割、是否披露未付对价、是否削弱盈利持续性|支持/反对/不足以判断标签与原文定位|只用于定位，重要冲突全部由主代理裁决；不能筛掉低相关度的反证|
|**后续：表格候选值选择**|在程序已提取的候选单元格中，哪个对应所需期间和会计口径|候选 ID；原值由代码原样复制|不能用 Jev 猜不存在的数值，不能让 score 插值得到财务数；金额、汇率、单位换算仍由代码处理|
|**后续：引用支持检查**|给定原文片段是否支持报告这条主张、是否反驳、是否信息不足|需返工的主张 ID 与来源位置|不把高分当真实来源认证，关键事实仍直接核验，数值一致性先用程序检查|
|**按需：子代理任务分流**|某份证据该交给哪项已有任务|任务标签|可多标签；少量任务直接由主代理安排，避免为调度本身增加调用|

官方已有“先快速检索，再候选重排”的示例，适合作为段落定位的架构参考；其法律数据示例不能直接证明中文投研效果。[重排示例](https://docs.typesafe.ai/cookbooks/rerank_typesafe)。

表格方案应采取“程序找候选 → Jev 选择候选 → 程序复制及标准化”的形式；数字仍可能因候选生成、列头关联或模型选错而出错，结构正确不等于财务口径正确。[候选值选择](https://docs.typesafe.ai/cookbooks/pre_parsed_value_extraction_cookbook)。引用检查也只提供筛查线索。[引用支持检查](https://docs.typesafe.ai/cookbooks/citation_check)。

## 4. 适合普通程序或主代理的部分

**普通程序优先**：公告日期比较、截止过滤、发行人标识核对、完整分页检查、下载与文件头校验、哈希去重、PDF 按页提取、已有事实的单位换算、财务合计、汇率和股本桥、价格地图、schema 校验。已有 `stock_price_map.py` 和 `research_paths.py` 应继续使用，不必换成分类模型。

**主代理保留**：完整 compact 覆盖、Precheck/Gate 的最终判定、机制和政策链解释、收入/利润率/倍数假设、现金安全垫、Terminal/TAM 同口径推导、风险去重和敏感性，以及实质冲突裁决与最终九节报告。不能把 R1–R20/D1–D8 压成一个“是否值得买入”的 Jev 问题。

官方明确列出 Jev 在精确数值、日期比较、多层推理及长杂乱上下文上的局限，且不以自由文本生成为目标。因此不建议让它写中间综述、算 V50/P1/P2、直接审定 Gate 或代替原文阅读。[已知局限](https://docs.typesafe.ai/model-jaggedness/jev-1.13)。

## 5. 本机接入的关键设计

已核实本机使用 `rashedInt32/jev-mcp` 包，版本 0.5.0；当前工具集有 ask/check/classify/score/triage/models。它不是检索中出现的另一同名 MCP 项目。配置中的 `JEV_FILE_ROOTS=off`，本次 triage 返回 `file_roots=[]`，服务端路径读取确实关闭。

这不要求放开全磁盘读取。推荐**本地程序读取本任务允许发送的公开材料，直接在代码层传给 Jev，模型上下文只接收筛选结果和选中的原文**。也可以用专用、受限的公开摘录目录承接路径读取，但需要明确配置与验证；本次保持现有配置。先让主模型完整读文，再把全文抄给 Jev，只能节省部分判断输出，无法省掉已经发生的主模型输入。

建议资料层流程：

`官方披露目录与原文 → 代码完成主体/日期/分页/版本检查 → 按页提取并保留表格边界 → 必读清单与关键词/BM25 候选召回 → Jev 多标签筛选/重排 → 主代理定向读原文和核验 → 现行框架与价格地图工具`。

程序返回的索引包含 `document_id / page / span_id / topic / probability / review_status / error`，完整分布与计量存 scratch。主代理必须看全部未决输入和反证状态，但无需看每条低风险候选的完整概率向量。Jev 本身不生成自由文字理由，可返回预先定义的原因标签；解释仍来自原文或主代理。

有两个批处理边界：

- 同一片段的多个独立问题合并到 `jev_ask` 或 triage 的 questions；题目需要自足，不能依赖另一题刚生成的答案。由代码组合结果。[多题并行](https://docs.typesafe.ai/patterns/fan-out)。
- 本机 `jev_triage` 一次 MCP 调用在内部对每个 item 各发一次 API 请求，并发执行、加总 usage；不是整批材料只计一次输入。同题说明也会随 item 重复计量，应避免堆叠无关问题。本机实现见 `/Users/xinquanzhou/.local/share/jev-mcp/node_modules/jev-mcp/dist/index.js` 第 460–505 行。

所有筛选标签仅表示“机器筛查”，不能提升为“已读原文”。错误、uncertain/review/abstain、未知选项都进入直接阅读路径。第一阶段只改变排序与任务分流，不允许分类器静默删除候选；后续在真实召回评估后才讨论减少低风险材料阅读。

缓存键应绑定文档内容哈希、段落边界、问题/选项版本、模型实际版本；涉及时点或规则时还要绑定截止日及相关框架哈希。框架更新后重新计算受影响的标签和判断。缓存原始披露可以复用，但复用前仍要查新披露、更正和版本变化。

## 7. 与类似方案的取舍

|方案|在本仓最合适的用途|主要取舍|
|规则、正则、哈希、按页索引、BM25|第一层粗筛、元数据处理和精确计算|优先做；无需语义模型。BM25 应考虑中文分词/字符 n-gram 和财务同义词，不能盲用英文分词默认值|
|Jev|多标签事件分流、附注主题定位、候选重排和变化预警|本机已可用，试点成本小；需要中文真实数据校准及保留不确定回退|
|本地多语言 reranker，例如 BGE reranker v2-m3|长期积累大量中文财报后，对查询—段落做相关性排序|可本地运行，减少外发；主要输出相关性，不替代多题分类和推理。需部署、算力及同样的召回评测|
|较小的生成模型 + 严格字段校验|确有自由文本/开放字段提取需求时|能生成值和解释，但增加幻觉与校验负担；先评测再决定是否值得增加第二种模型|

BGE 官方模型卡提供多语言 query–passage 打分和本地调用方式，其 sigmoid 分数不应直接解释为财务事实正确概率。本次没有安装或实测 BGE，不断言其速度或质量优于 Jev。[BAAI 模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)。

不建议第一步搭建复杂向量数据库或强行把所有判断改成 Jev。对本仓现阶段，页级索引、宽召回和窄语义筛选更容易验证收益。

## 8. 推荐落地顺序与验收

1. **先补计量和读取纪律。** runner 完成后另存 `usage.json`，保留 provider 原始字段、统计范围、模型与运行耗时；能取到子代理 usage 时显式去重汇总，取不到保持 unknown。增加按文档哈希/章节记录的读取清单；定位接口先返回位置，不直接回显数万字符。该清单不能在上下文丢失后阻止必要重读。
2. **再接两个 Jev 试点。** 一是候选公告分类，二是财报段落排序。与 `required_inputs` 直接对接，先做影子运行：记录分类结果，但不按标签剔除材料。临时索引放 output，不扩充最终 v2 JSON，也不创建第二份投资规则。
3. **通过真实样本比较后再扩展。** 新旧证据变化识别、反证标注和表格候选选择放下一批。以证据索引驱动失效重研，主代理继续负责全部适用框架覆盖。

具体改动点是后续实施建议：新增一个公开资料读取/筛选适配器、一个离线与真实 API 评测入口，在 `stock-research/references/data-acquisition.md` 接入定位输出，在后端技能说明标签不能代替核验，在 runner 汇总完成后计量。现行 canonical 和 compact 投资判据不需要因工具接入而改变。

对照组至少区分“当前执行”“只改确定性读取层”“再加 Jev”，使用同一冻结公告集合、框架、截止日和研究问题；分开记录冷/暖资料缓存。指标包括：

- 关键事实、反证、更正/重述、未付对价、受限资金的召回及漏读清单；失败/不确定项是否进入回退。
- 主代理直接核验的事实与原文口径是否一致；Gate、现金桥、Terminal、V50/P1/P2 是否出现可解释变化。
- 各宿主 input/cached/cache-write/output、全团队统计范围、Jev usage、工具调用次数和阶段耗时。
- 每个 required_input 实际送入主模型的材料量，以及重复读取是否用于必要核验；不能用文件大小替代真实 usage。

阈值应在独立中文评测集上按漏项代价选择，不直接把 MCP 默认 0.7/0.3 或 0.8/0.5 当生产标准。关键必读材料无论模型分数都要保留；批量低风险材料才适合逐步自动分流。验收需要比较筛选质量和成本，而非只追求更短报告。

整体收益尚未实测。架构上可写为：新开销 = 保留的深度研究开销 + 选中原文读取 + 筛选开销 + 回退开销；只有被省掉的主模型筛读与重复回合大于新增部分，才有净收益。若当前研究已经只读必要页面、瓶颈是估值推理，Jev 的边际价值会较小。
