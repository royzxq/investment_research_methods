# 自动深度调研

这是本地研究编排，不代表官方 Deep Research 产品或同等能力。可直接调用或由其他技能读取执行，不依赖名为 `Skill` 的调用 API。目录与通用技能映射遵循仓库 `research/README.md`，正式产物不写 `research/` 根目录。

## 输入与交付模式

- 必填：调研问题。可选：截止时间、地域/语言、来源要求、已有材料、报告/笔记路径、研究主题、`required_inputs`、`mode`，以及调用方选定的历史基线、`research_mode` 和接续清单。默认日期与截止日按 `Asia/Shanghai`；独立研究默认截止当天。`research_mode=incremental|full` 表示研究方式，与以下 `mode=standalone|backend` 的交付模式独立；不要求调用方改变最终 JSON schema。
- `mode=standalone`：用户直接要求深研时的默认模式，保存一份正式报告及证据笔记。默认报告为 `research/investment/studies/<slug>/<YYYY-MM-DD>/investment-deep-<YYYY-MM-DD>-<slug>.md`，笔记为 `output/deep-research/<YYYY-MM-DD>-<slug>/`。
- `mode=backend`：供调用方继续判断和写报告，`stock-research` 使用此模式。只保存证据笔记、来源索引和输入交接，不生成独立长篇综述，也不启动仅为改写笔记的综述代理。调用方负责完整最终报告；若用户同时要求独立报告，按明确要求交付。
- 路径相对仓库根，无仓库则相对工作目录；调用方指定路径从其约定。已有同名产物先检查，默认复用或追加序号隔离，不覆盖未获授权的文件。本技能不自动提交、推送或对外发送。
- `required_inputs` 标明名称、用途、已知值/缺口，数值带口径、币种、单位和期间，决定派工与验收；不能以“主题已搜索”作为完成。缺用户私有输入不阻断独立研究，也不允许推断冒充事实；仅询问无法合理确定的必需信息。

## 证据纪律

- 事实取证优先调用方指定的官方披露/数据入口；需要开放网页搜索时默认使用宿主内置检索与页面读取，暂不调用 `gemini-search` / `gemini_web_search`，也不先尝试 Gemini。把本轮取证路由、可复用原文及已知失败状态传给子代理，避免每个代理重复失败。OpenAI 产品问题遵循 `openai-docs` 的官方来源顺序。
- `stock-research` 后端遵循调用方传入的 [原始资料获取与核验](../stock-research/references/data-acquisition.md) 适用章节；独立研究按主题选原始发布者。公告目录返回的是资料线索，原文下载/文本提取也不自动升级为“已读原文”；分页未完、身份不符或接口失败不能当作“没有相关披露”的证据。
- 股票后端的批量公告/年报候选按 [Jev 条件路由](../stock-research/references/jev-routing.md) 提交本次公开候选，由程序决定是否调用并记账；不会删除候选或提高证据等级。已有精确范围、小任务记录跳过原因，Jev失败回退直接原文核验；不要求每个研究都强制产生API调用。
- 检索摘要只用于发现来源；关键事实须尝试打开原始公告、文件或数据。标明**已读原文／已读二手来源／仅检索摘要／未取得**；摘要不独立支撑估值、Gate 或其他关键结论，只读媒体不声称已读其引用的公告。
- 历史截止按公开披露日，不只按事实所属期间；后来资料单列事后信息，不混入当时结论。事实、假设、不可得分开；假设说明依据、合理区间和影响。主动找反证与替代解释，公开资料没有直接给出预测不等于不能形成有依据的假设。
- 共享材料可免重复下载和转录，不能代替独立核验。会改变估值、现金安全垫、Gate 或核心结论的关键事实，由主代理或另一核验者直接复查原文对应章节及口径，必要时另寻来源；多个代理引用同一文件不算多源印证。核验失败保留缺口，不能通过复制他人“已核验”标签提升等级。

## 1. 按缺口安排研究

先按调用方契约检查历史基线。后端优先核对调用方已选报告、接续清单及必要原文，不重复全量查史；独立研究先在用户材料及本仓对应主题归档内查找同对象、同问题的历史，按需追溯更早相关章节。核对对象/范围、实际证据截止、来源版本与可追溯性、口径、反证和方法兼容性；晚于本轮截止公开的信息隔离，不能仅凭报告估值日较早就采用其中事后材料。适用历史存在时默认 `research_mode=incremental`，没有适用历史、核心基线失效或用户明确要求完整研究时用 `full`，在本轮交接记录基线路径、来源归属、截止、版本或已有哈希与选择理由。基线摘要只作导航，不能自行获得原始证据的核验等级。

局部过期、缺证、错误或方法变化先处理受影响项；若重大对象/业务/治理变化、广泛重述或核心来源不可追溯，使原核心逻辑无法接续，则扩展为完整研究。后端发现调用方基线失效时回报失效范围，由调用方协调调整；子任务不自行重做全部主题。完整研究仍可复用适用原文；时效标准沿用调用方，不另创统一缓存有效期。

派工前建立覆盖表作为接续清单：**问题/输入｜上期事实或假设及证据位置｜本期处置及理由｜本期值/证据或缺口｜影响的判断/估值/监控｜负责人**。按影响结论的问题分项，可合并同源条目，不为列清单重复转录全部历史。处置分为：

- **沿用**：来源可追溯、口径适用，检查新增披露/修订后仍成立；保留原事实日期与定位。旧假设须重新检验依据，不当作已验证事实；关键事实仍按证据纪律直接复查原文。
- **更新**：新披露、事件、时效性读数或有依据的假设调整；说明与上期的差异及影响。检查从上期实际覆盖范围到本期截止的变化，补查原覆盖缺口，不能因索引或旧报告没有记录就认定无变化。
- **纠错**：上期事实、单位、比较期、计算或解释错误；记录旧说法、正确值/口径、原始出处及受影响结论，后端交调用方重评，独立模式自行重评；不把纠错混写成公司经营变化，也不覆写历史。
- **待补证**：上期未决项或本期缺口/冲突；列补证需求、实际尝试与结果、对结论的限制及后续检查条件。未取得、不适用和已核实无变化分别说明；新增的待补证项不能冒充沿用事实。

全部适用问题均须有去向；只为新增、变化、纠错、待补证和必要的关键事实复核安排任务。任务数量由缺口、依赖和风险决定，无固定 3–6 个代理要求；可由主代理直接完成小任务，也可合并同源问题。并行任务划清边界，关键事实独立核验是有意重叠。stock-research 优先补齐会改变机制、Gate、估值和 Terminal 的信息；调用方仍执行全部适用框架判断，不沿用旧 Gate 或旧价格替代本期裁决。

在调用方工作目录建立单一来源索引（如 `sources.md`）和输入交接（如 `handoff.md`）；简单任务可同一文件分节，不为凑文件重复内容。索引记录来源编号、原始 URL、标题、披露日、事实期间、实际读取位置，以及本地副本路径/版本或哈希（如有）；网页可变时保留读取日期和相关摘录。只保存必要章节与定位，不把整份原文反复打印到对话。缩略内容不足以判断时继续读取上下文，不能裁掉附注和反证。

指定索引唯一写入者；子代理只写各自独占笔记，回收后由主代理合并新增来源。同一资料首次获取/提取指定一个负责人，其他任务复用可读副本或按需取原文，避免共享文件并发改写。PDF 优先本地按页提取，读取所需章节、表格及相邻附注；乱码、扫描件或表格错列时回看原页或使用可用 OCR 并核对关键数字。提取操作本身不需要模型，送入模型的文字仍消耗 token；不以硬截断原文替代核验。

## 2. 最小上下文派工与证据笔记

使用宿主实际提供的协作工具，按并发槽分批。默认独立上下文：Codex 的 `spawn_agent` 使用 `fork_turns="none"`；其他宿主选择等效能力，无法控制继承时不声称已隔离。主代理不默认把整个聊天、全部框架、数据包或全部旧报告传给每个代理。

每个任务单必须自足：问题与边界、公司/市场/截止、相关用户约束、所需输入、必要已知事实及异常、证据/反证纪律、适用规则原文及版本、共享来源位置/编号、独占输出路径和验收要求。增量任务另给相关基线条目、原文定位、本期处置及待验证假设/反证，不把全部旧报告发给每个代理，也不让其重复调研已覆盖项目；关键核验仍保留。只给相关章节或定位，允许按需回查更广上下文；重要限制和依赖不能只留在未继承的聊天。代理发现跨主题依赖返回主代理协调，不自行重复展开整套研究或层层派生。主代理保留全框架覆盖责任。

笔记按证据条目写，不写重复的公司简介和长篇综述。推荐条目：**编号｜事实/假设/不可得与值或区间｜单位/币种/期间｜来源编号及原文位置｜核验状态/强度｜支持或反对方向｜影响的输入/结论**；来源编号须可定位索引或本笔记新增来源。解释性文字用于机制、假设依据、替代解释和冲突；不以固定字数或来源数量上限截断研究。完整原文读取仍遵守引用限制。

代理返回笔记路径、关键输入/证据编号、反证及缺口，不在消息里粘贴笔记全文。主代理检查任务状态与文件内容；失败由主代理补做或记录未完成项。无子代理能力时主代理执行同一契约并披露方式，不省略证据要求。

## 3. 裁决冲突并定向补研

主代理读取全部输入状态、反证和冲突条目，再按编号定位证据；不为整合而串接打印所有笔记。先区分日期、口径、币种或会计处理造成的表面冲突，再回查原始资料。对影响核心结论的冲突，记录双方说法、出处、裁决依据与下游影响，不把互斥事实带入单一基准情景。

最多**一轮**定向补研，可含 1–2 个任务，优先关键冲突与会改变结论的缺口，不重复完整初研。仍无法裁决时给分别有依据的条件情景；不能约束合理区间则阻断受影响结论，继续交付其他部分。此轮次边界不免除最终核验、已发现错误的修正或缺口披露。

## 4. 一次成稿与验收

对每个 `required_inputs` 在输入交接列出：**名称｜值或区间及口径｜事实/假设/不可得｜证据编号与核验状态｜残余不确定性/冲突裁决｜影响的下游结论**。没有清单时以研究问题的关键结论验收。交接引用证据，不逐条重写完整笔记；必须显式列出反证及未决项，不能只挑支持基准情景的摘要。

回收后更新同一接续清单，列明沿用／更新／纠错／待补证的实际结果（无项明确无）；上期关键假设、反证和监控须交代得到支持、被证伪或仍未决及依据，移出跟踪要说明原因。新发现错误须检查下游影响，不能留在笔记而继续使用旧输入。清单可与既有事实底稿/交接合并，不另造长篇中间综述。

- 后端模式：主代理验收交接后由调用方直接写最终报告，保留其要求的完整推导、出处和规则判断；不另复制一份中间综述。
- 独立模式：默认主代理一次写正式报告，交代研究方式与基线、四类处置及结论变化的原因，保留可独立阅读的本期论证和关键原始出处，不能只写差异并要求读者回翻旧报告。只有明确的独立交付需要或复杂度确有必要时才交给专门写作者；写作者读取交接和相关证据，并是该报告唯一成稿者，主代理核验而不再整篇改写第二版。

逐个检查应有文件存在、非空且含承诺内容；核对关键数值、反证、假设、冲突裁决及缺口与原始证据一致。交接摘要不替代原文核验。完整论证和关键出处须在正式报告中可复核，不能只依赖 scratch 笔记。材料只支持条件结论就明确条件；缺口仍在标明“部分完成”，不伪称全部通过。研究假设是否满足调用方框架由调用方裁决。

## 5. 交付与开销记录

返回本模式的文件路径、简短结论、执行方式及限制哪些下游结论的未决项；对话摘要不能替代落盘，也不能把“找到来源/生成文件”说成完成核验。

在本次 scratch 交接末尾简记研究方式、任务数量、沿用／更新／纠错／待补证范围及仍未决项。宿主提供实际用量时记录总输入/输出 token、缓存用量（若有）、统计范围及是否包含子代理；拿不到就写“token 用量不可得”，不以字符数代替或宣称节省比例。不得为节省 token 降低关键核验、删除适用问题或截掉不利证据。
