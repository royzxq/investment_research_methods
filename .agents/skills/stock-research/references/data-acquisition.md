# 原始资料获取与核验

补充公开资料、检查新披露或解决数据冲突时读取；子代理只接收其市场及任务需要的章节。本文件不改变投资框架、估值门槛或最终轻量 JSON 合同。查询记录、原始响应、PDF 和提取文本存本次 `output/stock-research-.../`，复用 `sources.md`/`handoff.md`，不另建最终结构化证据包。

## 1. 按问题选择来源

| 所需事实 | 优先入口 | 用途与边界 |
|---|---|---|
| A 股财报、回购、融资、诉讼、交易进展 | 巨潮及所属交易所披露网站；发行人投资者关系网站补充 | 查询目录后取得公告全文，摘要版不能代替相关报表和附注 |
| 港股财报、通函、股本及重大事件 | 披露易；巨潮港股栏目作补充入口，发行人网站补充 | 巨潮与披露易的覆盖、语言及更新时间须分别检查，不能假定完全相同 |
| 政策、处罚、行业供需与 TAM | 发布政策/处罚的监管机构、统计机构、行业组织及可核验的企业原始资料 | 公司公告不能替代全行业证据；核对统计定义、地域和样本 |
| 行情、汇率、标准化财务序列、一致预期 | 已有数据包和实际可用的数据服务/官方发布源 | 标明日期、频率和口径；卖方预测与公司披露分开，不能靠搜索摘要补成完整序列 |

一般路径是“原始发布者查询 → 下载原文 → 本地定位/提取 → 核验对应章节”。不知道发布者、需要竞争对手/产业链线索或官方目录有缺口时，用内置搜索发现，再回原始发布者。搜索并非所有任务的最后一步，也不能替代原文核验。官方平台承载发行人披露，不保证文件内容无误；多个站点转载同一公告不是独立经济证据。

## 2. 公告查询的共同契约

1. **确认主体**：保存公司全名、市场、证券代码及本入口内部标识；A+H、同名企业、历史更名和同一公司的不同证券须区分。代码是字符串，保留前导零。返回目录及下载文件还须核对公司，不能只凭请求参数认定匹配。
2. **明确时间窗**：历史研究按公开披露日期/时刻截断，区分财报期间与事件生效日，日期统一到 Asia/Shanghai。分别覆盖模型所需历年财报和“上次核验至本期截止”的新披露窗口。接口默认区间不代表研究区间；日期边界可重叠抓取后去重。实时研究记录查询时刻，不声称覆盖尚未结束的当天。
3. **验证响应和覆盖**：校验 HTTP 状态、实际内容类型、JSON 结构/错误字段、发行人及日期范围。HTML 错误页即使 HTTP 200 也不是成功。根据实际分页/总数/下一页标记读完所选区间；命中平台上限时拆分日期窗口，重复页、截断或中断记“部分取得”。标题检索用于定位，检查新重大事件时也查看该窗口不带关键词的公告目录，避免只搜财报漏掉风险。
4. **保存可追溯记录**：在共享来源索引记入口、参数、查询时刻、覆盖区间、分页状态与异常；每份选中资料记原始链接、标题、主体、披露时间、版本/更正关系、本地路径和 SHA-256。目录/下载/提取完成度与“已读原文”核验状态分开。响应或公告数量只是本次查询结果，不证明全历史完整。
5. **筛选与去重**：下载覆盖 `required_inputs`、反证与重大事件的文件，不把成百上千份无关公告全部送入模型。同一公告的双语版/重复附件关联处理，更正、重述及补充公告保留各版本；历史截止后更正不回填为当时已知。零结果先核对标识、日期、筛选条件和服务响应，再用官方页面或另一原始入口确认；无法确认则记查询缺口，不能推断“无公告/无风险”。

## 3. 巨潮：A 股与港股的候选共用入口

从 [巨潮官网](https://www.cninfo.com.cn/) 当前查询页面确认请求。以下是网页查询接口的使用线索，不是稳定开放 API 契约；每次研究按实际响应验证，不继承历史联调对可用性的断言。

| 操作 | 入口与关键参数 | 核验点 |
|---|---|---|
| 查发行人标识 | `/new/topSearch/query`，候选参数 `keyWord=<代码或名称>`、`maxNum=10` | 从实际返回/页面选中主体取得 `orgId`，核对市场及全名；不可用时从官网公司页/证券列表确认 |
| 查公告目录 | `/new/hisAnnouncement/query`，表单 POST；`stock=<代码>,<orgId>`、`column`、`tabName=fulltext`、`pageNum`、`pageSize`，日期区间候选 `seDate=YYYY-MM-DD~YYYY-MM-DD` | 保留实际筛选条件，检查 `announcements`、总数及 `hasMore`/页数（如有），逐页核验 |
| 取附件 | `announcements[].adjunctUrl`；相对路径用 `https://static.cninfo.com.cn/` 解析，绝对链接按实际返回 | 验证真实文件及主体、标题、披露版本；附件 URL 不等于已读证据 |

用户实测提供的样例：A 股茅台 `column=szse`、`stock=600519,gssh0600519`；港股腾讯 `column=hke`、`stock=00700,hk00700`。维护本技能时未完整复现，须按本次返回确认。它们不是证券代码生成 `orgId` 的通用公式；`column` 也不是上市市场判定。裸代码查询为空时先确认完整标识，不能认定没有公告。优先 HTTPS，不把某次 HTTP 成功视为所有环境可用。

## 4. 披露易：以当前标题查询页为准

从 [披露易标题查询](https://www1.hkexnews.hk/search/titlesearch.xhtml?lang=zh) 选发行人、语言和日期窗口。用页面实际证券检索返回的内部 `stockId`，不要把五位证券代码直接填入 `stockId`，也不要沿用别家公司的编号。官方 [标题查询脚本](https://www1.hkexnews.hk/ncms/js/titlesearch.js) 将证券代码/名称与内部 `stockId` 分开处理。

`/search/titleSearchServlet.do` 是待按当前页面请求核验的查询入口；参数、方法、会话和分页以官方页面及其引用的查询脚本为准。用户提供的响应字段包括 `FILE_LINK`、`DATE_TIME`。若外层 JSON 的 `result` 是 JSON 字符串，按类型再解码一次；不执行返回内容。保留公告/发行人标识、标题、时间、语言及附件链接；相对 `FILE_LINK` 按响应站点解析。实际结构不同则回页面核对，不套固定模板。维护时读取页面/脚本不等于已完成 servlet JSON 联调。

选中所需财报/通函后检查全文、相关附注及之后的更正，必要时对照另一语言；“业绩公告”“年报”可能是不同文件，不能因年度一致互相替代。可使用截止日已公开的业绩公告中已核验字段，缺少附注单列，不以尚未发布的年报补齐，也不因此自动阻断全部估值。查询所得文件继续执行第 2、5 节验收。

## 5. PDF 本地提取与数字核验

- 同一原文只由一个负责人下载/提取，其他任务共享副本。下载设置超时并检查状态、文件头和可解析性；先写临时文件，完整后记录哈希。PDF、原始响应和全文文本留本地，模型读取所需页及上下文，不反复打印整本年报。
- 优先使用已有 `pdftotext`，缺少时用可用 Python 的 `pypdf` 按页 `extract_text()`；保留 PDF 页边界，不自动安装依赖。命令示例（路径和页码替换成本次原文）：

  ```sh
  pdfinfo input.pdf
  pdftotext -layout -enc UTF-8 input.pdf text.txt
  rg -n '现金流量|受限|担保|关联|Cash flows|restricted|contingent' text.txt
  pdftotext -f 18 -l 20 -layout -enc UTF-8 input.pdf -
  ```

- 关键词只用于定位。读取完整相关表格、章节及相邻附注，遇到跨页表格继续上下页；同时记录 PDF 页序（从 1 起）与报告印刷页码（如有）。文本行号不能单独替代最终报告的页码/章节。
- 检查空页、乱码、扫描图片、单位/负号丢失、双栏错序、跨页表头等提取问题。用可用 PDF 渲染/页面截图查看原页；需要时用已有 OCR，再逐项核对关键数字。不能恢复则该字段标“未取得”，不把识别乱码作为 0。
- 保留列头、期间、币种、单位、合并/母公司、归母/总利润、审计状态及重述口径。流量指标区分单季/累计/全年，期末股本与加权平均/稀释股数分开。关键合计做算术抽检；现金桥核对受限资金、经营必需现金、债务、租赁及承诺支付/已付款，区分余额日与期后变动，避免重复扣减。EV 到股权价值的桥另核对少数股东等权益调整，不混作可用现金。发现冲突回原文裁决，不只调折扣。
- 本地解析不使用 LLM，不意味着全文进入模型零 token。节省的是重复下载、全文传输和转录；关键事实独立复核、反证、附注及估值论证照常完成。原文关键 URL、披露日期与页码/章节保留在正式 Markdown；最终 JSON 仍仅 `meta/price_map/monitoring`。

## 6. 失败回退与质量验收

新准备的 DSH `data-health-v1` profile 在原生 `web_fetch` 与 `mcp__aktools__get_data` 的工具执行前后自动检查；旧冻结 profile 保持原行为。每次尝试的 `data-health/` 保存原始返回和含哈希的体检记录，主、子代理共用。该检查不覆盖 bash/curl、PDF、其它 MCP 或 stock-x；这些路径继续执行前文同等的来源、期间、单位及覆盖核验，不因没有自动记录而豁免。

叠加 `evidence-recovery-v1` 的 DSH 新批次，还会对网页截断/空壳、PDF不支持和分页不足自动尝试一次补证，记录在本次 `evidence-recovery/`。直接公开 PDF 链接可用 `research_recover_evidence(url)` 下载和按页提取；已有 gap_id 的分页可续补。每轮最多补3页、每页最多1000行、每数据集最多3轮；文档同 URL 去重，失败后换可核验入口，不反复重试同一请求。公共文档下载上限32 MiB，扫描页和受保护/超限文档保留缺口。

补证返回索引后，用 `research_read_evidence` 搜索定位并读取所需页/章节及相邻附注；PDF 的 part 为从1起的页序，文本 offset/limit 为字符范围，表格则为行偏移/行数。渲染原页仅生成图片，仍须实际看图核对。对实际读取的 receipt_id，用 `research_record_evidence_use` 记录采用范围、相关输入、理由及报告章节，或明确未解决/未采用；不把读到片段等同于全文核验。最终报告继续保留原始来源 URL、披露时间、页码/章节和口径限制，补证工具的声明记录不能替代报告引用。

效果统计区分材料取得、读取凭证和研究者声明采用；最终引用是否成立仍需核正文，不能把统计中的 retrieved 或 used_for_scope 当作程序验证的事实。该闭环是 DSH 工具能力，Codex 直接取数不自动执行；共用的证据与缺口规则对两端都适用。

- 取数前确认证券代码为字符串、市场及实际接口参数；按需要指定窗口/分页。程序拒绝已知财务接口的含混主体和非法分页，未知接口不套用已知字段定义。
- 取数后分别看 `rejected`（该次返回存在机械错误）、`review_required`（部分取得或待核口径）、`mechanical_checks_only`（仅机械检查未发现问题）。三者均不证明事实真实或正文完整。主体/接口冲突重新取证；空结果不写成无公告/无风险；合法零值、负利润不视为缺失。
- 分页记录核 offset、实际行数和总数，并检查本次同参数已取得范围及重复/变化页；尾页 `truncated=true` 不自动判失败。`complete_observed` 仅指本进程观察到该响应表的全部行，不证明历史披露完整或数据新鲜。只需特定期间时可在确认覆盖后停取，正文注明范围，不强制下载全部历史。
- 财报期间与公开披露日分列，估值日后披露/期间不能用于本轮历史判断；接口没有披露日则回原文确认。单位/币种缺失不得靠市场猜测；原值、单位及转换依据、采用值分别留底，不自动补零或除以100。
- 正文截断、仅导航/脚本或短 HTML 会提示补证；短文不自动判无效。对所需章节完整性进行语义核验，必要时完整下载或定向浏览器补充。已有可靠片段可以支持局部事实，但不能据此声称全部原文已读。
- 在现有来源索引/交接中引用体检记录、待补输入及其影响范围；不要把任一辅助字段缺失扩大成整家公司不可估值。价格、资格和持仓控制继续按现行框架判断。机械检查失败也不意味着本轮研究必须终止，可走后述替代来源。

同一路径失败后先核对参数和原因，至多一次有依据的重试；仍失败转官方页面、交易所/发行人原文或内置搜索定位替代原始链接。遇到登录、限流或访问限制不循环重试；需要渲染且工具已可用时使用浏览器/抓取能力。把已尝试入口、失败类别、缺失输入和下游影响交接给主代理，避免各子代理重走失败路径。

不新增固定搜索厂商依赖；Parallel、Exa、Bocha、Firecrawl 等仅在当前可用且适合具体缺口时考虑。安装、付费或提供新凭据不由研究请求自动授权；厂商排名、免费额度及“零幻觉”不作规则。选择新工具时可用同一组真实问题比较中文公告、港股英文材料、监管记录与行业数据的原文取得率、事实正确性、漏项及重试/费用，先验证改善，不把工具数量当质量标准。

交接验收以输入和证据为准：已核验值/假设区间/不可得、原始位置、查询覆盖及残余冲突均可追溯；找到标题、下载成功、提取成功不能代替关键事实核验完成。数据未取得只限制受影响结论，继续已有证据能支持的研究；不得为让价格地图非空捏造事实或预测。

## 7. 长正文与压缩后的证据接续

长正文留在本次原件目录，按缺口搜索和分段读；摘要只保留研究进度、关键证据定位、未决冲突及下一步，不能替代原文。进入估值链的数字及可能推翻结论的反证，保留主体、期间、币种、单位、披露日、原文位置与采用范围。未知仍为未知，冲突与反证不能在压缩时被归并成肯定结论。压缩后使用关键数据前，按定位重读相关表格及相邻附注。

叠加 `evidence-context-v1` 的 DSH profile 提供独立于会话的 `evidence-context/`：已允许的原生 web_fetch 文本及补证闭环的 HTML/PDF/文本自动登记；补证 PDF 复用原件，不重复下载。持久记录按来源及摘录哈希标识，短定位簿作为 DSH required runtime context 重新装配，正文不常驻提示词。

1. `research_find_evidence()` 列来源；传 query 可找关键标记。锚点有省略时，仅传该 source_id，并按 evidence_next_offset 传 evidence_offset 续查全部锚点；传 source_id+query 则在原文定位，返回 next_search 时带其 part/offset 继续查后续片段。命中不是已读，索引超出显示预算时有省略提示。
2. `research_open_evidence(source_id, part, offset, limit)` 读所需片段，默认2400、最多4000个 JavaScript UTF-16 代码单元；PDF part 为从1起的页序。返回稳定 evidence_id；后续传 evidence_id 校验原件和摘录哈希重读。保持同一工具的定位口径，不把 Python 行号/字符偏移直接当作该 offset。扫描空白页不会生成文字证据。
3. 关键输入及反证用 `research_pin_evidence` 登记标签、口径和 support/counterevidence/unresolved/rejected 状态。标注是研究者判断；默认 required_citation=true。确实未采用时写明理由并设 false；拒绝证据保留拒绝理由，不能作为支持引用。未知字段省略，不编造单位或披露时间。
4. 裁剪/压缩后先从定位簿或索引找回，再用 evidence_id 重读。短簿最多显示6条，并提示未显示数量；未显示不代表问题已解决。来源变化、文件丢失或哈希不符时停止使用该引用，另取可核原文。
5. `research_cite_evidence` 返回带原始URL、PDF页序/文本位置及隐藏 evidence-cite 标记的 Markdown；如带 quote，必须是已读片段中一段逐字短引文。正式正文原样保留该 Markdown，仍在邻近文字补足披露日、章节/印刷页码和口径。`research_check_citations` 自检后，runner 对最终暂存报告再次检查，未知引用、改字/改链接/改页码、原件变化及必引证据漏引会阻止该次发布。

检查通过只证明已登记引用与保存原文的机械对应，不证明正文推论正确、披露真实、完整覆盖全部关键事实或全文已读。没有登记/引用时记录 not_exercised，不能报“引用已核验”。统计分别记录打开、主动重读、自动引用检查和最终报告检查；不从这些计数推定压缩提高了研究质量。运行原件与定位簿依赖该次 output 目录留存，删除后无法本地重读。

该原生插件不自动覆盖 AKTools 表格、任意 bash/curl、本地文件或其他 MCP；这些材料继续使用既有读取凭证、原文与位置记录。Codex 共享上述取证和压缩接续原则，但不会自动执行 DSH 的原生工具、定位簿及引用验收。
