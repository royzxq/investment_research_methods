# 冻结旧批次的 v3 交付附录

仅当 runner 已验证冻结批次要求 `stock-research/v3` 时读取；普通新批次和自由运行不使用本附录。它保留旧交付语义，不使旧方法成为当前两价候选的方法。canonical/compact 使用该批次原始冻结正文，旧报告/JSON/封口不改写。无法证明原合同或快照缺失时停止恢复并新建批次，不使用活跃默认 writer 猜测旧合同。

旧构建必须显式传 `--legacy-snapshot <本批run/framework-snapshot/manifest.json>`；工具验证快照和 prepared 绑定，新 v4 批次不能借此写 v3。旧审计使用 [legacy-audit-v1](legacy-audit-v1.md)，不读取活跃 audit-v2 要求。以下是保留的旧报价契约（其中“新交付”仅指本被冻结旧批次）。

审计按冻结快照：只有 research_validation=stock-research-audit/v1 才强制旧审计；原无强制审计的批次不因本附录正文中的“新runner”表述被追溯加门。

# 估值与轻量输出契约

本文件是 `stock-research` 的报价提取与导出接口，不是第二份投资框架。规则、固定数值和强制映射以 canonical 为准。研究阶段按框架论证 P1/P2，完成原始报告后再提取其最终报价；导出不得重做研究结论。

研究计算及发布门禁见 [旧研究一致性](legacy-audit-v1.md)：报告内保留一份可核算输入与程序生成的可见表，校验利润桥、风险归属、基线折扣变化及冻结/解除合取。新runner批次强制检查，最终v3结构与忠实报价提取不变；计算检查只拒绝矛盾，不自动更改报价。

## 研究假设如何形成

1. 收入、利润率、估值锚分别列低/中/高情景、证据日期、适用口径和最脆弱假设。利润须区分经常经营、一次性收入与估值收益；不得仅复制卖方目标价。
2. 对 `d_base/r_chip/r_v5/r_gov/r_terminal`，在报告列“已在盈利/倍数中反映的风险→仍需覆盖的风险→本次取值及理由→敏感性”。无额外风险时可论证取 0，不代表缺证据默认无风险。
3. canonical 的标准/上沿/一档未给绝对数值时，先解释本公司可接受的研究区间，再选基准；从严约束选择所论证区间的上侧。所有这些是**本次研究假设**，不是用户账户参数或框架常数。若范围无法论证，补研、换合适模型或给真正不可估结论，不为避免 null 任填折扣。
4. 敏感性至少展示最重要假设变化对 V50/P1 的影响，并核对是否改变结论。敏感性结果不自动成为最终 P1 区间；报告须明确最终采用的 P1 单价或区间及各值含义，不为 JSON 凑齐三档。报告原有 P1 与框架算式冲突时，先回查并在报告内裁决，导出不得静默改价。
5. `step_down` 只能在 canonical 的 5%–10% 内选择并说明理由。仓位上限缺失时 cap 留在报告参数化，不影响价格计算。取消 P2 不把其原 40% 自动转移到 P1。

## 导出 v3（仅三个顶层键；历史 v2 原样读取）

| 对象 | 固定字段 | 语义 |
|---|---|---|
| `meta` | `schema_version, code, name, valuation_date, currency, report_path, generator` | 新交付 schema 固定 `stock-research/v3`；报告路径相对仓库根；币种为上市报价币种；新产物 generator 为 `codex` 或 `claude` |
| `price_map` | `mode, reason, v50, p1, p2, t1, t2` | 全部数值价格统一为报价币种/股；没有仓位、Gate 全树或证据副本 |
| `monitoring[]` | `variable, current, as_of, trigger, action, source, next_check` | 1–10 项，变量不重复；当前值不能与报告底稿矛盾 |

- `mode`：`buy_candidate` 买入型候选、`tracking` 跟踪、`observation` 观察、`frozen` 冻结、`rejected` 否决、`unavailable` 因输入不足不可估。它是研究用途，不是下单许可；除买入型可为 null 外，`reason` 必须解释限制。
- 前三种模式必须有数值 `v50={low,base,high}` 和非空 P1 报价对象。P1 单一明确报价用 `{"base":22.42}`，不带 low/high；报告另有明确上下沿时才带 `low/high`，两个边界须成对、正数且有序；只有区间时用 `{"base":null,"low":20,"high":24}`，不得补中点。若同时有 base，须在区间内。`base` 保留为稳定读取键，null 明确表示原报告没有单一基准价，不表示拒绝全部 P1。不同独立候选价或互斥方案不是上下沿，先完成语义裁决。不得从 V50、折扣、敏感性表或另一端报价重建 P1。
- `frozen` 分两类：仅市场状态/相关事件临时限制且公司事实可靠时，在报告完整核算新 V50/V5（V5 留报告）、折扣和观察 P1，再提取明确报价，mode 保持 frozen、reason 解释买入限制；公司真硬失败或核心事实不足时 P1 留 null，旧 frozen 空值继续有效。`rejected/unavailable` 不产新 P1/P2；允许在 v50 保留此前核验参考值，报告注明来源/失效边界，没有则 null。
- `p2={status,price,reason}`：`active` 有效参考价；`cancelled` 按规则取消，价格 null；`suspended` 暂停触发，保留计算参考价格和恢复条件；`unavailable` 不可计算，价格 null。除 active 外均必须理由。**frozen 有观察 P1 时只能 suspended/cancelled，禁止 active**；旧 frozen 空 P1 与 rejected/unavailable 只能 cancelled/unavailable。观察 P1/P2 没有新开仓、加仓含义；tracking 下 active 仅指跟踪参考有效，不代表可以买入。
- runner 在方法/证据接续未确认时，可将旧方法下已完成的有价结果保存为隔离修订：派生 JSON 用 `frozen`、P2 暂停/取消，reason 明示待复核，保留原估值；原始暂存报告、JSON 与回执不改，不自动提升 latest。此为输出版本隔离，不另创金融门槛，也不要求无依据重算或删除研究。
- `t1/t2={price_condition,events}`：前者为价格条件，后者为非空事件条件列表。 `price_condition` 只写本轮价格条件，现价、行情日期及距阈值百分比放报告；引用 V50 边界优先写“接近 V50 上沿”，需要列数值时从最终 V50 回读，不手工保留旧数字。T2没有适用价格边界时明确写“当前不适用：原因”；T1按下列固定表达式交付，理由留报告，不捏造数值阈值。接近 V50 上沿/明显高于 V50 如需量化，必须在报告注明研究假设，不能称为框架固定比例。
- `monitoring.current` 为数值、明确带单位的文字或 null；非空必须有 `as_of`，不能晚于估值日。来源写可追溯 URL/公告章节或数据包字段；`trigger` 包含窗口、单位和方向，`action` 指定重算/撤价位/取消 P2 等动作。`next_check` 为日期或明确事件文字。未取得当前值时 current/as_of 可 null，原因及补证路径写报告，不用 0 代替。
- **新T1交付门禁**：`build`、`check`与runner发布前共用程序校验。`t1.price_condition`只接受一个完整表达式（允许空白）：明确金额`股价≥30.85元/股`（CNY可用元/CNY，HKD可用港元/HKD），或`接近V50上沿时复核`、`接近V50下沿时复核`、`接近V50基准时复核`；相应V50值必须存在。无独立T1、按既有V50基准回退时用基准引用。金额须有限正数，CNY最多2位有效小数、HKD最多3位，不能靠程序舍入修改报价。
- 明确无价格条件时仅用`当前不适用`或`本轮不提供T1报价`，理由留报告。冻结/跟踪等执行限制不是拒绝报价：有本轮观察T1仍按金额/引用交付，不为了通过格式校验清空报价。公式（例如34.28×90%=30.85）、比例假设、现价、行情日期和距阈值百分比只写报告，JSON取已论证的明确30.85；多报价未裁决时先完成研究裁决，不能任选一个或转换成无报价。
- 校验失败时修正scratch输入或暂存JSON并重新check，回读最终金额核对报告；不截断未知注释、不伪造公式或擅改经济含义。runner未通过交付校验不会发布，仅沿用现有最多一次输出失败重试。旧封口加载保持原结构协议，历史文件不重写。T2仍遵循原引用校验；T1门禁本身不改变报价语义、不判断事实或估值合理性。

- 字段不再重复保存 precheck/rules/valuation 全推导/terminal/qualitative_findings/key_inputs/gaps。折扣、cap、评级、解除条件和其它框架必答仍保留在报告；schema 精简不等于研究删项。

新生成必须标注 `meta.generator`，含义为实际执行宿主。历史 v2 缺此字段仍可校验和作为未标注来源的历史读取，不自动归类 Claude 或 Codex；用户明确要求历史重提取时仍保留该来源缺口，不能把重提取宿主标成原研究生成端。

## 大模型价格提取与裁决（组装交付前）

由执行本轮`stock-research`的大模型阅读最终报告价格节，完成提取、消歧和取值，再核对候选JSON；程序负责结构、数值与状态校验。不把程序报格式错当成模型拒绝报价。先完成下列语义自检，再填 v3 字段：

1. **逐字段确认本轮最终含义**：P1取报告本轮最终明确单价/base；仅明确区间时保留边界、base=null；无明确 low/high 不补造。P2按本轮明确有效/暂停参考价或取消/不可得状态显式提取，缺价不在导出中代算；T1定位明确卖出阈值/复核起点。区分`有效报价`、`明确撤回/拒绝`、`未找到`和`仍有歧义`；现价、日期、百分比、估值上沿及P1/P2只是各自字段，不能混作T1候选。旧值、历史例子、另一端结论不冒充本轮报价。
2. **T1取值优先级**：唯一明确的本轮数值起点且未被撤回→用该起点；仅明确V50上沿/下沿/基准→用对应值；无独立T1且无拒绝、无边界指定而本轮有有效V50→用base并明确标记兜底。真正明确拒绝或价格条件不适用时才交付相应无报价表达式，说明原文依据。冻结/tracking/suspended及“当前持有不卖”是执行状态，有明确观察报价就保留。
3. **兜底止点**：P1 多个独立报价未裁决、缺价但未明确拒绝、V50文字/对象真实冲突、只有比例而无明确数值起点、无适用V50的未知缺项，都不能靠base、任选最低值/平均值、重算或清空字段绕过。先在本轮报告内裁决；仍无法确定则用failed回执说明缺项/冲突及所需澄清，保留旧生产数据。研究端不把P1/P2改成V50或他端报价；P2的共识属主派生不冒充模型建议。
4. **算术与精度**：例如“≥30.85元，等于上沿34.28×90%”→T1=30.85；34.28是计算锚、22.80是现价，二者都不是另一卖出阈值。用确定性十进制工具核对公式、边界与原文精度；程序负责数值一致性，大模型负责解释字段归属。自动交付CNY2/HKD3位有效小数；过精度先核对源报告并明确修订精度和理由，不让程序暗改报价。仅有90%没有明示金额，不将计算结果冒充已提取报价。
5. **清晰交付与回读**：在既有报告价格节记录所选值、状态、原文位置/引句、排除的行情/旧值及引用或兜底理由；P1/P2明确报价写相应字段，T1写上节单一表达式与事件条件，不新增审计键。按“报告→报价提取输入→build/check→回读实际输出”逐值核对一致性。格式错时模型定向提取/消歧后重新交付，不能仅改文字使检查通过而改变经济含义。

首次输出失败后，现有一次重试会提供原错误与本轮同端暂存草稿位置。它们是未验收数据，先核对股票/生成端/日期和本轮冻结输入，只读第一次草稿并写新的retry目录；仅语义/格式问题优先定向修正，不默认重新取证和估值。缺草稿、输入/来源失效或实际研究问题按原研究流程补证，哈希/路径/结构门禁照常。重试后仍失败就保留失败回执，不循环调用模型。人工自由文本录入另按ai仓交易决策skill取值及两位小数约定，不将其三席7天规则用于自动批次。

## 报价导出工具

先完成报告和最终价格裁决，再组装临时报价提取输入，放本次 `output/stock-research-.../`；生成候选 JSON、完成回读和语义验收后，再移到未占用的最终日期路径。工具保留 P1/P2 输入报价，不读取自然语言自动猜价、不取行情、不判 Gate、不更新 latest、不覆盖文件。

```sh
python3 scripts/stock_price_map.py build --legacy-snapshot <本批run/framework-snapshot/manifest.json> --generator codex --input output/<本次目录>/quote-input.json --output output/<本次目录>/investment-<代码>-<日期>-price-map-codex.json
python3 scripts/stock_price_map.py check output/<本次目录>/investment-<代码>-<日期>-price-map-codex.json
```

临时输入只有 `meta, mode, reason, valuation, p1, p2, t1, t2, monitoring`。除 valuation 的单位换算外与最终字段同义；`p1` 与 `p2.price` 均由报告显式提供。旧 discounts/step_down 输入拒绝，不保留重新推价分支；折扣与步长论证仍在报告。meta 可省略 schema_version，工具自动补齐 v3，显式旧版本拒绝新建。CLI 必传 `--generator codex|claude` 并补入 meta；与已有 meta.generator 冲突时拒绝。输出文件和 meta.report_path 的文件名必须按代码、估值日、生成端和可选 `-rN` 后缀配对，Claude 运行将上述 codex 替换为 claude。

`valuation` 二选一：

```json
{
  "kind": "equity_value",
  "values": {"low": 486, "base": 630, "high": 792},
  "currency": "CNY",
  "unit": "100_million",
  "shares": 2214000000,
  "fx_to_quote": 1
}
```

上例只是单位接口演示，不代表本期正式研究结论。`equity_value` 是归属于普通股股东的权益价值，不能直接填 EV；unit 仅 `currency/million/100_million`，股份数为实际股数，不是“亿股”。

```json
{
  "kind": "per_share",
  "values": {"low": 19, "base": 31, "high": 50},
  "currency": "HKD",
  "unit": "per_share",
  "fx_to_quote": 1
}
```

每股模式不再传 shares。跨币种必须补 `fx_source`（出处、日期、方向）；`fx_to_quote` 定义为“1 单位输入币种等于多少报价币种”。例如 1 HKD=0.865 CNY，HKD→CNY **乘 0.865**，CNY→HKD **乘 1/0.865**。同币种只能为 1；工具无法判断经济上正确的汇率方向，必须独立用反向等式验算。

以下报价对象仅演示格式，实际金额逐项提取原报告：

```json
{
  "p1": {"base": 22.42},
  "p2": {"status": "active", "price": 16.00, "reason": null}
}
```

只有原文另给区间时，P1 才可为 `{"base":22.42,"low":17.29,"high":28.18}`；原文仅给 17.29–28.18 时用 `{"base":null,"low":17.29,"high":28.18}`。单价不复制成三个相同值，区间不求平均。原报告多报价、公式与明示金额不一致时先裁决，不能为了通过校验改数字。

临时冻结且可估时，报告仍须完整论证 valuation/折扣/step_down，导出使用已明确的观察 P1/P2。frozen 不提供观察 P1、以及 rejected/unavailable 时 p1=null、P2 为 cancelled/unavailable 且 price=null，valuation 可 null。取消的 P2 永远没有数值；暂停 P2 保留原报告参考价格但不得表述为有效执行档。历史 v2（含 frozen 空值）默认不自动转为 v3；用户明确要求重提取时逐份读取对应原报告，保留真实空值、状态和来源归属，同步依赖哈希、latest 与既有消费回执，不冒充新一轮研究。

P1/P2 价格统一为交易币种/股，CNY 最多 2 位、HKD 最多 3 位有效小数；超精度拒绝，先在报告明确精度修订，不静默舍入报价。V50 仍可十进制换算单位/股本/汇率后按上述精度舍入，不参与 P1/P2 导出计算。构建拒绝非有限数、布尔伪数值、重复键、错误币种和状态。

build/check 核验 P1 单价/区间、精度、状态、T1 单一表达式及 T1/T2 的显式 V50 引用。P2 active/suspended 必须有明确正价格；当 P1 有明确 low 时继续核对其 5%–10% 关系（允许最终舍入容差），无 low 只校验 P2 低于已报 P1，不把 base 偷换为 low、不代算缺价。v3 不强加 P1 与 V50 三档逐档对应，研究公式及合理性由报告审阅。程序不能证明报价来自原报告；逐值来源、公式冲突、汇率桥、Terminal、现金桥及监控基线仍须大模型独立复核。

## 验收后发布到本地

- 正式报告必须含本次研究的数值、单位、来源、假设和敏感性，以及明确最终 P1/P2；不要求用户翻 scratch 才能复核价格。
- JSON 与报告同一生成端、同一版本、同一隔离后缀（如 `-price-map-codex-r2.json` 与 `-research-codex-r2.md`）；报告 §0 记录数据包和两个框架的指纹及本次证据截止。新增来源、参数或证据状态变化都不能只凭旧文件存在而复用。
- `output/indexes/investment/<市场>-<代码>/investment-<代码>-latest-<生成端>.json` 只缓存同一生成端截止日内最近合格的正式 v3/v2 配对，保持与日期 JSON 完全相同；`research_paths.py latest-company --generator <生成端>` 同口径；省略生成端或指定 `unattributed` 只查旧的未标注文件，`rebuild-indexes --as-of <日期>` 按该截止日重建，找不到合格配对时清除该公司的旧缓存。选择按估值日期而非格式版本、修改时间或价格是否非空：较新的 frozen/rejected/unavailable v2/v3 仍优先，禁止回退到旧的有价结果。
- v1 只可经 `latest-company --generator unattributed --include-legacy` 作为历史研究读取，不参与当前价格缓存。若日期更晚的文件仍是 v1，明确告知“最近合格价格地图估值日”和“较晚 v1 历史日”，不能把旧空值误当本次结果，或把较早 v2/v3 重新标成后日期估值。隔离版不更新 latest；升级须用户已有明确授权。
