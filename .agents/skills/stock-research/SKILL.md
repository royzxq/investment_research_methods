## 入口与边界

- 自然语言“使用进行股票投研：<股票信息>”“使用 stock-research 进行股票投研：<股票信息>”或显式 `$stock-research` 都进入本流程；解析股票信息后直接执行研究并本地保存，不只给操作说明。
- 生成端按实际宿主固定：Codex 使用 `generator=codex`，Claude Code 使用 `generator=claude`，DeepSeek Harness 使用 `generator=dsh`。它表示本次研究的生成端，不是行情来源或引用报告作者；不从旧文件或所读技能目录推断。新报告、JSON、scratch 和 latest 均按生成端隔离，具体命名见输出契约。
- 从技能目录向上定位包含 `framework/`、`research/` 的仓库根，主代理先读根 `AGENTS.md`、`docs/context/project-state.md` 和完整 `framework/investment_framework_compact.md`；同一版本已读内容不重复整篇加载，子代理上下文按研究后端契约裁剪。方法和歧义以 `framework/investment_framework.md` 对应原文裁决。下列仓库路径相对根目录。
- 按 compact §10 输出 0–8 九节报告；最终 JSON 仅含必要标识、P1/T1 价格地图、研究控制摘要和重点监控变量。完整证据、参数论证、Gate 判定及缺口留在 Markdown。
- 日期采用 `Asia/Shanghai`。估值日默认当天；历史研究按**公开披露日**限制证据，不只比较财报期末日。D1–D8 按已采纳方法结合截止日内最新兼容观测重新判断，旧段落中的“当前”只代表原观测日；按原规则刷新受影响状态不等于修改宏观方法、阈值或权重。缺证保持 unknown，未采纳方法不作生产有效规则；本工作区的已授权影子任务明确绑定候选版本，不冒充已采纳。
- runner 提供 `framework-snapshot` 时，主、子研究统一使用其中冻结的 canonical/compact 及已采纳状态输入，禁止执行中改读工作区最新正文；批次指纹指向这些实际正文。手工复评用 `python3 scripts/investment_maintenance.py select --date <估值日>` 核对最新已采纳状态、方法兼容性、估值截止与证据来源，再冻结本轮输入；无兼容接续记录时沿用方法原文并补证受影响状态，不能拿未采纳提案或过期读数替代。状态触发只登记待复评，完成须有同一对象、证据截止及方法的实际报告；研究完成不等于账户执行。
- **交付版本先判定**：普通新交付使用 v4 + audit-v2。runner 已验证旧冻结批次要求 v3 时，按原审计要求（audit-v1 或原无强制审计）改用 [legacy-v3-output](references/legacy-v3-output.md) 和 [legacy-audit-v1](references/legacy-audit-v1.md)，并用原冻结框架；既有 prompt/input/hash 保持原字节，运行器附加的版本路由优先于本技能默认交付。无法恢复原合同则保留旧批次、新建任务，不混用新技能默认 writer。
- 批量公告分流或年报候选章节定位按 [Jev 条件路由](references/jev-routing.md) 执行。runner 默认 `auto`，先提交公开候选 manifest，由程序判断阈值并记录调用/未调用原因；不能口头判断无需 Jev 后省略记录。排序不删除证据，原文和语义核验继续由当前宿主主模型完成。
- 只做研究。不给下单金额、执行时间或账户分批计划；不交易，不自动 commit/push/开 PR。同日运行先检查旧文件，未获覆写授权则复用或隔离。

## 输入与复评

- 需要唯一确认公司、上市市场与估值日；可从明确代码解析名称。只有名称/代码冲突、A+H 市场不明确等会改变研究对象的问题才先询问。
- 数据包是现有量价、估值和财务输入的优先来源。正文、文件或粘贴文本均可；缺标题、附录或整节不自动中止。无数据包时先寻找用户已提供材料或公开原始资料建立底稿，不声称仓库存在 `stock_data_pack.py`，不凭记忆补值。
- 仓位上限为可选用户输入。收入、利润率、估值锚与风险折扣由本次研究论证；**不要求用户替研究者完成估值**。没有账户参数只影响报告里的 `cap_final`，不影响 P1 可计算性。
- 用 `python3 scripts/research_paths.py latest-company --market <SH|SZ|HK> --code <代码> --as-of <日期> --generator <生成端>` 查找截止日内最近完整正式 **v4/v3/v2** 报告/JSON 配对，按 `meta.report_path` 读取报告。新交付使用 v4，旧 v3/v2 原样读取。`--include-legacy` 仅用于另找旧 v1 历史材料；旧 `valuation.v50` 须确认单位，旧示例参数和空值地图不得直接变为本期结论。本端没有结果时另用 `--generator unattributed` 查无来源历史、或显式指定另一端作参考；不能将其冒充本端结果。默认命令没有结果时继续研究，不以旧 v1 冒充有效价格地图。只查按日期归档的公司目录，不依赖 latest 缓存、不自动提升隔离版。
- 区分估值日期、实际运行时间与格式版本：后运行的历史估值报告可能日期更早；后日期 v1 不得覆盖 v4/v3/v2 缓存。若存在更晚的旧版报告，披露两者日期并检查其新增事实，不把较早结果说成已复评至请求截止日；晚于截止的事实仍隔离。
- 数据晚于历史截止时隔离该字段、定向补找当时版本；新鲜度不足时先补证。只有身份、历史配置或核心估值事实仍无法确定且需要用户独有资料时，集中询问具体缺项；其余可独立完成的研究继续。

### 历史基线与研究方式

- **默认选择**：发现适用历史报告时采用 `research_mode=incremental`；没有适用历史、核心基线失效，或用户明确要求完整研究时采用 `research_mode=full`，记录理由。两者均执行下文全部适用框架判断，交付完整九节报告；增量只改变取证范围，不降低研究与验收标准。`research_mode` 只记在报告与后端交接，不新增最终 JSON 字段，也不替代价格地图的用途状态。
- **选定基线**：优先检查截止日内最近的本端正式报告，读取其来源、关键事实与假设、反证、缺口及监控，不把全部历史全文逐份载入。需要追溯纠错或假设变化时再读更早相关章节。正式配对查无结果不等于没有历史报告；在同公司日期归档内补查旧 v1 或仅有正文的材料，核对对象、日期、生成端与来源后决定能否复用证据，不能据此认定存在有效价格地图。跨端及无来源标记报告只能作为明确归属的参考材料，关键事实回原文核验、本期假设独立论证；不以他端目标价作为本期取值依据，不自动提升隔离版或采用已撤回结论。
- **适用性与失效**：核对研究对象、业务/合并范围、证据截止、来源可追溯性、数据口径与本轮框架。方法或 schema 变化不自动作废历史事实；局部过期、缺证或错误先定向更新、补证或纠错。重大业务/治理变化、广泛重述或核心证据不可追溯，使原经营与估值逻辑无法可靠接续时转完整研究，注明失效范围；仍适用的原始材料可继续使用。不能仅凭报告较新或价格非空判定适用，也不因旧报告冻结、否决或不可估而退回更早的有价结论。
- **建立接续清单**：派工前按 [deep-research-auto](../deep-research-auto/SKILL.md) 的覆盖表逐项明确“沿用／更新／纠错／待补证”、理由、原位置及对判断/估值/监控的影响；保存在本轮既有事实底稿或交接内，不另写长篇历史综述。行情、汇率、股本、现金/负债、事件窗口及监管状态按各自时效检查，最新披露仍滞后时保留日期与缺口，不推断期后余额。重新检验收入、利润率、倍数、折扣等旧假设的依据，不能把研究预测当成已验证事实。
- **检查变化并定向取证**：从上期实际核验的披露范围接续至本期截止，覆盖新财报、公告、重大事件、相关行业/政策变化和上期监控触发；原查询不完整或截止不清的部分先补齐，不能仅查上期报告日之后、不能因未提新事件就认定无变化。只派发新增、变化、纠错、待补证及必要的关键事实复核；完整框架覆盖责任仍由主代理承担。研究中发现基线失效时调整范围并更新研究方式及理由。

## 1. 自检与计算依赖

- 按 compact §2 做时效、缺失、异常检查，建立单一事实底稿：字段、值、单位、财报期间、披露/行情日期、来源、核验状态。合理包内字段直接引用，不重复查算。
- 异常、缺失、口径冲突字段允许定向核验原始公告；保留包内原值和新证据，说明采用/隔离理由。未解决的异常不能作 Gate/熔断硬依据；研究假设不能冒充历史事实。负 PE 可能源于亏损，先检查估值方法适用性。
- 一致性抽检须同期间、同币种、同股本口径；`PB≈PE×ROE` 仅在口径匹配时有意义。港股不稳定列名须核对报表定义，不硬映射；没有 A 股扣非科目不等于通过盈利质量检查。
- 采用调整后/非准则利润时，按[财务定义与估值分歧复核](references/valuation-and-output.md#财务定义与估值分歧复核)核对公司定义、调节表和研究口径。对影响估值的定义冲突安排独立原文核验，核验者先读原文与待核字段，不先接受拟采用结论；没有独立核验能力则主代理复查并披露方式。不得把计算通过或多个代理复述视为原文已核实。
- R1 所需**板块**换手分位不得由个股换手分位代替；缺口记无法判定，个股换手仅为辅助证据。北向/南向持仓须带实际数据日与披露频率。
- 建立 `required_inputs` 清单传给后端：估值收入/利润率/倍数或适用模型参数；股本、净债务和币种换算；Terminal 同口径 TAM/份额/稳态利润率；可能改变 Gate、加仓资格、逻辑失效和退出条件的证据。不再派发 P2/T2 报价或步长论证任务。每项说明作用、已知值、缺口、所需出处，区分估值阻断、买入资格限制及普通注记。
- 需要新增公开资料或检查新披露时，按 [原始资料获取与核验](references/data-acquisition.md) 执行：公司公告优先查巨潮/披露易等官方披露入口，政策与行业数据查对应原始发布者；搜索用于发现及补漏。先核对发行人身份、披露区间和查询完整性，再下载所需原文、本地按页提取；接口空结果或抓取失败不代表没有公告。正常包内字段仍直接沿用，关键事实及异常按上述规则核验。

## 2. 自动深度研究

读取并执行 `.agents/skills/deep-research-auto/SKILL.md`，不依赖名为 `Skill` 的工具。用当前宿主的子代理能力调度（Codex 使用可用协作工具，Claude 使用可用代理工具），按可用并发槽分批；没有子代理时主代理执行同一取证契约并披露降级。

传入：`mode=backend`、公司、估值截止、用户约束、已知事实及异常字段、`required_inputs`、输出契约，以及上述取证 reference 的适用章节、已确认的发行人标识、已查披露区间/分页完成度、共享原文位置和本轮接口失败状态。另传 `research_mode` 及选择理由、基线报告路径/生成端/实际证据截止/版本或已有哈希、接续清单及相关原文位置；无适用基线时明确说明，不让后端重复全量查史。工作目录为 `output/stock-research-<市场>-<代码>-<日期>-<生成端>[-rN]/`；共享来源索引、事实底稿、主题笔记与输入交接放在其中，不覆盖前次 scratch。后端不另写长篇综述、不默认启动综述子代理，主代理直接据交接与证据写最终九节报告。以下是覆盖清单，**不是固定代理数量**；按实际缺口与依赖合并/拆分任务，已有充分适用证据的项目记录依据后不重搜：

1. 经营、客户、订单、交付、回款与盈利现金流；形成收入和利润率的区间依据。
2. 产业竞争、供给/价格、政策第二环、TAM 与份额上限；明确分子分母和地域口径。
3. 估值锚、可比口径、资本结构、股本、汇率及 V5；卖方预测只作外部参照，区分经常利润与一次性项目。
4. 治理、筹码、拥挤度、国家队、分红与再融资；国家队动作仅按官方披露确认。
5. 公司事件、D6 在册窗口及适用指数/温度读数；只为当前公司补输入，不改 D 层配置。

后端可以提出估值假设与计算输入，不代主代理作买入裁决。正常包内字段不重复查；异常字段、关键事实交叉核验是明确例外。保留反向证据；打开媒体正文不等于打开其引用的公司公告。

交接须检查实际任务状态、证据笔记与输入交接存在且非空；读取全部输入状态、反证与冲突条目，按证据编号定位相关笔记，避免先全文串接再重复改写。关键结论仍回查原始来源对应章节，不以交接摘要替代核验。按 `required_inputs` 汇总“已核实事实／有依据的假设区间／不可得”。先裁决影响 V50、现金安全垫、Terminal 或 Gate 的冲突（如收购是否交割、款项是否已付），不得把互斥事实同时带入模型。确实无法裁决时建立分别可核验的条件情景；不能约束合理区间则阻断受影响估值，不以任意折扣掩盖。最多一轮补研优先解决这些项。

## 3. 框架判断

按 compact 顺序执行，下列清单只提供导航，不创设新判据：

- **Precheck §4**：10 闸、硬失败清单逐项记录来源/证据/约束，使用通过、警惕、不通过、不适用、无法判定。完成主矛盾、收益逻辑、双轴及 D8 内需暴露必答。缺数据不等于通过，某一子项不通过也不自动替代硬失败清单。
- **机制 §5**：六型、当期权重/状态/分支；正反馈与周期反转鉴别、R8/R15/R19 的适用性。研究覆盖权重不等于买入放宽。
- **Gate §6**：逐分支记录；Non-Price Risk、联动约束与 R6 逐窗口暴露/预案齐备，无实质暴露可说明依据后不适用，过窗按实际影响及时复核。温度缺失不得默认冷档。价值可估性与买入资格分判：真实公司硬失败/治理红线或核心事实不足，按 canonical 停止新 P1；仅市场/相关事件临时冻结且事实可靠，继续完整 V50/V5、Terminal、折扣与观察 P1，保留 `frozen` 及解除条件，新建仓/追加均受阻，不能以 tracking 隐藏冻结。
- **估值 §7**：按生意选方法，给收入/利润率/估值锚的低、中、高假设及 V5。R3 的三项合取逐项判断，不把任一未知当命中或通过；盈利对冲按原文证据门槛判定。适用的 R14 油价压力情景、R20 内需情景不能因无法精确量化而默认为通过。
- **Terminal §8**：A 股与港股固定参数、四步推导、可达性和预期差。负 PE 的隐含倍数不用于正常盈利可达性判断。TAM、份额和稳态利润率先研究同口径区间，不因没有“官方稳态预测”就全部交回用户；公开事实不足以支持假设时明确保留缺口。
- **Price Map §9**：逐项核对强制映射，包括 R1/R3/R5/R6/R9/R14/R17/R18/R19/R20/R21 和 D5 状态。R9 缺项或 D5 承接暂停等限制买入资格时，事实可靠者继续估值；D5 深化冻结仍用 frozen 输出观察价，非冻结的跟踪/观察限制用对应 mode。取消本轮追加/暂停追加/加仓从严分别列当前约束与解除依据；R21 退出仅回等待复核，不直接恢复买入或追加，原重建路径独立可用。

## 4. 估值参数与数值交付

计算前必读 [估值与轻量输出契约](references/valuation-and-output.md)。关键约定：

- 新自动交付及本次复评按 [研究一致性](references/research-consistency.md) 生成报告内唯一核算表与审计块，闭合收入→经常利润→股权价值→V50/P1链；独占风险归属、同端基线折扣变化和全部阻断的合取解除均在发布前校验。按 [共享证据与恢复验收](references/acceptance-gates.md) 另生成唯一验收块及可见表，不能仅自报 R14 passed，正文恢复逻辑须与各 scope 的全部有效约束一致。检查不替代原文/语义核验；新交付为 v4 + audit-v2，既有利润桥/风险归属/折扣检查保留，旧历史不追溯改写。

- canonical 已有数值必须沿用；未规定绝对档位的 `d_base/r_k` 是本次分析假设。研究者给证据、取值理由、区间/敏感性与风险去重说明，再选基准值。不得称其为框架默认值，也不创建通用折扣表替代 canonical。
- 最终价格统一为交易币种/股。总市值与每股价值分开输入；EV 先明确扣净债务及其它权益调整。汇率写清方向，股份数用实际股数。
- 新研究仅给 P1/T1；P2/T2 及 step_down 已退休，不换名称重建。临时市场/相关事件冻结但可估者保留完整估值与观察 P1/可论证 T1，entry/add 均受阻；公司真硬失败、否决或不可估不产新 P1，持仓处置仍可进行。历史空值可读，不补造本期价格。
- 先完成估值、完整条件表与最终报价裁决，再用 `scripts/stock_price_map.py build --generator <生成端>` 从 scratch 明确输入导出 v4。P1 单价只写 `{"base":报价}`；原文有明确区间才保留 low/high，仅区间则 base=null，不补中值；导出不从 V50/折扣重算 P1、不补上下沿。T1 仅取有效价格表达式，事件进入独立条件。V50 单位/股本/汇率换算仍可用工具。完整假设与算式留报告。
- 组装交付前按 [输出契约的大模型价格提取与裁决](references/valuation-and-output.md#大模型价格提取与裁决组装交付前) 逐字段确认有效报价/明确拒绝/未找到/歧义及T1兜底依据；语义难判由本轮大模型裁决、程序只作数值与交付校验。收到失败反馈时先针对原草稿定位错误，不能靠清空报价或改估值假设绕过。
- T1 只保留价格型评估起点。全部适用的加仓、逻辑失效、复评/减仓和退出条件独立列稳定 ID、当前事实/状态、作用范围、动作和解除/重新研究依据；证据未确认不直接宣告失效。账户缺失时报告给 cap 公式、首笔60%/预留40%的研究纪律及缺项，不给账户分配、不把预留转首笔。

## 5. 监控、验收与保存

- monitoring 最多保留 7 个公开可查核心项目，不凑数，可为 0 项：优先最脆弱估值假设、现金流、逻辑失效及有实际影响的公开行业指标，按重要性排序并合并重复观察；完整适用条件与有效阻断全部留报告及审计，不受展示上限截断。控制相关项目的 ID/kind/state 与审计同 ID 相符，普通经营跟踪不强造约束。
- 入选前用普通搜索实际定位并读取无需内部权限或付费订阅的公开原文；优先公司公告/财报、监管披露及公开行业统计。source 写机构、文档/指标、披露期和章节或 URL，public_search 写实际使用且可复现的检索词。URL、搜索摘要及模型自述不等于核验。内部订单、私有渠道数据、访谈及付费终端指标不进入日常摘要；有报告依据才改用公开替代指标，没有则在完整报告保留局限和未解风险，不造新指标。
- 每项有当前事实及日期（缺失为 null）、可观测触发判据、具体动作、来源和下次检查事件/日期。每项一两句，保留期间、触发、动作和公开检索路径，不重复研究推导；公开披露路径已确认但窗口未到可 current/as_of=null，缺数据不视为正常。无合格项用 monitoring=[] 并在报告说明。事实基线来自同一底稿；定性判据可用，但不能只有“关注”。区分框架阈值与本次分析阈值；假设与当前事实分开写在报告。
- 按[监控触发与交付复核](references/valuation-and-output.md#监控触发与交付复核)逐项区分当前已满足条件、下一观察期和解除条件；恶化触发不能同时写成关闭该告警。待取得的采购/套保/模型现金桥不因列入清单就成为可持续观察指标。仅在当前事实与阈值期间/口径一致时判断是否已触发，缺证不臆定状态。
- 接续验收：逐项交代上期关键假设、反证、缺口与监控的本期结果（得到支持／被证伪／仍未决）及证据；移出监控清单要说明原因，不以未披露视为达标。纠错须保留旧说法、正确口径与来源并重评受影响估值和判断，不改写历史报告。报告在相应章节说明结论、V50/P1/T1、用途及独立控制状态的变化来自新事实、假设调整、框架变化或纠错；无变化也给依据。旧价只作注明日期的对照，不冒充本期报价。
- 节省开销不通过缩减适用问题、硬截断证据字数、减少关键事实独立核验或跳过敏感性来实现。主代理核对完整框架覆盖及跨主题依赖；研究深度按未决风险扩大。
- 人工语义验收：关键证据冲突已裁决或明确影响；报告九节与 DCS 完整；币种/股本/现金桥/Terminal 算术正确；风险没有重复扣减；报告与 JSON 的 V50/P1/T1/研究控制/监控基线一致，P1 的每个已填值均能定位报告原句/表格、未填上下沿未被补造；非买入价位不含执行许可。
- 数据验收：新披露查询的市场/主体/日期范围及分页缺口已交代；关键估值事实能定位原始文件、版本与页码/章节，抽取表格的单位、列头和附注已核对。取得公告目录、下载 PDF、文本提取和读原文核验是不同状态；未完成项写入报告对应缺口，完整取证仍留报告，最终 JSON 只在 monitoring 增加公开检索词 public_search，不复制完整证据。
- 估值修订后，从最终 JSON 的 V50/P1/T1 回读核对引用和距现价百分比；build 不重写 T1 文本。控制另核报告/audit/摘要一致性，不能报价更新而沿用已经失效的旧 eligible。
- 新交付运行 `python3 scripts/stock_price_map.py check <JSON> --require-monitoring-quality` 与 `python3 scripts/research_consistency.py check --report <报告> --price-map <JSON> --require-lifecycle --require-acceptance`；分别验证报价/精度/T1 引用/监控交付/控制结构、证据绑定与按 scope 的全部恢复条件。已验证的旧冻结合同不追加新参数，按其原验收分支运行。它们不证明原文提取语义、来源真实性、经济风险不重叠或估值合理性。
- 最终文件：`research/investment/companies/<日期>/<市场>-<代码>/investment-<代码>-<日期>-research-<生成端>.md`、`research/investment/companies/<日期>/<市场>-<代码>/investment-<代码>-<日期>-price-map-<生成端>.json`。生产正式流程验证完成后按输出契约选择同一生成端截止日内最近正式 v4/v3/v2，刷新 `output/indexes/investment/<市场>-<代码>/investment-<代码>-latest-<生成端>.json` 为所选日期 JSON 的完全相同副本；`meta.report_path` 始终指向对应报告，不因格式新旧越过较新估值日。新完成的正式研究按此规则刷新本端 latest；隔离复评仍不自动覆盖正式产物。
- 同日同一生成端已有产物先核对报告 §0 的输入/框架指纹与证据截止。完全匹配且未要求复评可复用；其它情况自动选择未使用的 `-r2/-r3…` 同后缀报告和 JSON，隔离运行不刷新 latest。只有用户明确授权才覆写原文件或提升隔离版；不能因旧指纹缺失假定输入相同。
- 报告 §0 记录生成端、运行模式、`research_mode` 及理由、数据/证据日期、框架版本及 SHA-256、已提供数据包指纹、隔离/复评来源及基线实际证据截止，摘要列出沿用／更新／纠错／待补证范围和依据（无项明确无）；完整推导、本期结论所依赖的关键事实及其原始来源和页码/章节仍直接保留在报告，不能只引用旧报告或被忽略的 scratch 目录。
- 回执从实际最终 JSON 回读生成端、估值日、schema、用途、P1 单价/实际区间、T1 和 entry/add/holding 控制、关键监控及精确路径。历史四价仍为历史；null 区分不可估、P1仅区间无base、明确未提供T1与提取失败。不能把全 null 或缺控制的包称为有效买入交付。报价歧义不得掩盖已验收风险收紧：交属主按输出契约处理 control-only，不自行修改生产文件。
