# 个股调研与价格地图

输出目录、通用技能映射与发现命令统一见仓库 `research/README.md`；正式产物不写 `research/` 根目录。

## 入口与边界

- 从技能目录向上定位包含 `framework/`、`research/` 的仓库根，主代理先读根 `AGENTS.md`、`docs/context/project-state.md` 和完整 `framework/investment_framework_compact.md`；同一版本已读内容不重复整篇加载，子代理上下文按研究后端契约裁剪。方法和歧义以 `framework/investment_framework.md` 对应原文裁决。下列仓库路径相对根目录。
- 按 compact §10 输出 0–8 九节报告；最终 JSON 仅含必要标识、价格地图和监控变量。完整证据、参数论证、Gate 判定及缺口留在 Markdown。
- 日期采用 `Asia/Shanghai`。估值日默认当天；历史研究按**公开披露日**限制证据，不只比较财报期末日。D1–D8 按当时适用框架引用，披露过期或未适配报告，不自行更新宏观配置或框架。
- 只做研究。不给下单金额、执行时间或账户分批计划；不交易，不自动 commit/push/开 PR。同日运行先检查旧文件，未获覆写授权则复用或隔离。

## 输入与复评

- 需要唯一确认公司、上市市场与估值日；可从明确代码解析名称。只有名称/代码冲突、A+H 市场不明确等会改变研究对象的问题才先询问。
- 数据包是现有量价、估值和财务输入的优先来源。正文、文件或粘贴文本均可；缺标题、附录或整节不自动中止。无数据包时先寻找用户已提供材料或公开原始资料建立底稿，不声称仓库存在 `stock_data_pack.py`，不凭记忆补值。
- 仓位上限为可选用户输入。收入、利润率、估值锚、风险折扣与 5%–10% 内的 `step_down` 由本次研究论证；**不要求用户替研究者完成估值**。没有账户参数只影响报告里的 `cap_final`，不影响 P1 可计算性。
- 用 `python3 scripts/research_paths.py latest-company --market <SH|SZ|HK> --code <代码> --as-of <日期>` 查找不晚于估值日的最近完整正式报告/JSON 配对；有结果则按复评处理。只读 `research/investment/companies/<市场>-<代码>/<日期>/`，不依赖本地 latest 缓存，不自动选取隔离版。v2 使用 `meta.report_path`；旧 v1 使用 `meta.provenance.canonical_file` 找到日期 JSON，再定位同次报告。旧 `valuation.v50` 的单位须从报告确认，不把总市值当每股价格，不把旧示例参数直接转为正式结论。找不到上期材料可继续首次研究并说明。
- 复评先核对框架/数据版本、上期来源与缺口，并检查截至本期的新财报、公告、重大事件及监控触发；不能因旧报告未提新事件就认定没有变化。历史事实仅在来源可追溯、口径适用且未被修订时沿用；行情、汇率、股本、现金/负债、窗口与监管状态按各自时效更新。将各项标为“沿用及理由／更新／补证”，只派发剩余研究，但重新检验旧估值假设是否仍有依据，并运行全部适用框架判断、估值和价格计算。旧证据不可追溯或重大业务/治理变化使基线失效时，扩展为完整研究。
- 数据晚于历史截止时隔离该字段、定向补找当时版本；新鲜度不足时先补证。只有身份、历史配置或核心估值事实仍无法确定且需要用户独有资料时，集中询问具体缺项；其余可独立完成的研究继续。

## 1. 自检与计算依赖

- 按 compact §2 做时效、缺失、异常检查，建立单一事实底稿：字段、值、单位、财报期间、披露/行情日期、来源、核验状态。合理包内字段直接引用，不重复查算。
- 异常、缺失、口径冲突字段允许定向核验原始公告；保留包内原值和新证据，说明采用/隔离理由。未解决的异常不能作 Gate/熔断硬依据；研究假设不能冒充历史事实。负 PE 可能源于亏损，先检查估值方法适用性。
- 一致性抽检须同期间、同币种、同股本口径；`PB≈PE×ROE` 仅在口径匹配时有意义。港股不稳定列名须核对报表定义，不硬映射；没有 A 股扣非科目不等于通过盈利质量检查。
- R1 所需**板块**换手分位不得由个股换手分位代替；缺口记无法判定，个股换手仅为辅助证据。北向/南向持仓须带实际数据日与披露频率。
- 建立 `required_inputs` 清单传给后端：估值收入/利润率/倍数或适用模型参数；股本、净债务和币种换算；Terminal 同口径 TAM/份额/稳态利润率；可能改变 Gate 的证据。每项说明作用、已知值、缺口、所需出处，区分估值阻断、买入资格限制及普通注记。

## 2. 自动深度研究

读取并执行 `.agents/skills/deep-research-auto/SKILL.md`，不依赖名为 `Skill` 的工具。用当前宿主的子代理能力调度（Codex 使用可用协作工具，Claude 使用可用代理工具），按可用并发槽分批；没有子代理时主代理执行同一取证契约并披露降级。

传入：`mode=backend`、公司、估值截止、用户约束、已知事实及异常字段、`required_inputs`、输出契约。工作目录为 `output/stock-research-<代码>-<日期>[-rN]/`；共享来源索引、事实底稿、主题笔记与输入交接放在其中，不覆盖前次 scratch。后端不另写长篇综述、不默认启动综述子代理，主代理直接据交接与证据写最终九节报告。以下是覆盖清单，**不是固定代理数量**；按实际缺口与依赖合并/拆分任务，已有充分适用证据的项目记录依据后不重搜：

1. 经营、客户、订单、交付、回款与盈利现金流；形成收入和利润率的区间依据。
2. 产业竞争、供给/价格、政策第二环、TAM 与份额上限；明确分子分母和地域口径。
3. 估值锚、可比口径、资本结构、股本、汇率及 V5；卖方预测只作外部参照，区分经常利润与一次性项目。
4. 治理、筹码、拥挤度、国家队、分红与再融资；国家队动作仅按官方披露确认。
5. 公司事件、D6 在册窗口及适用指数/温度读数；只为当前公司补输入，不改 D 层配置。

后端可以提出估值假设与计算输入，不代主代理作买入裁决。正常包内字段不重复查；异常字段、关键事实交叉核验是明确例外。保留反向证据；打开媒体正文不等于打开其引用的公司公告。

交接须检查实际任务状态、证据笔记与输入交接存在且非空；读取全部输入状态、反证与冲突条目，按证据编号定位相关笔记，避免先全文串接再重复改写。关键结论仍回查原始来源对应章节，不以交接摘要替代核验。按 `required_inputs` 汇总“已核实事实／有依据的假设区间／不可得”。先裁决影响 V50、现金安全垫、Terminal 或 Gate 的冲突（如收购是否交割、款项是否已付），不得把互斥事实同时带入模型。确实无法裁决时建立分别可核验的条件情景；不能约束合理区间则阻断受影响估值，不以任意折扣掩盖。最多一轮补研优先解决这些项。

## 3. 框架判断

按 compact 顺序执行，下列清单只提供导航，不创设新判据：

- **Precheck §4**：10 闸、硬失败清单逐项记录来源/证据/约束，使用通过、警惕、不通过、不适用、无法判定。完成主矛盾、收益逻辑、双轴及 D8 内需暴露必答。缺数据不等于通过，某一子项不通过也不自动替代硬失败清单。
- **机制 §5**：六型、当期权重/状态/分支；正反馈与周期反转鉴别、R8/R15/R19 的适用性。研究覆盖权重不等于买入放宽。
- **Gate §6**：逐分支记录；Non-Price Risk、联动约束与 R6 逐窗口预案齐备。温度缺失不得默认冷档。真正 Precheck 硬失败、冻结或否决按 canonical 停止后续买入型计算；给理由及解除/复评条件，不通过出数来规避 Gate。
- **估值 §7**：按生意选方法，给收入/利润率/估值锚的低、中、高假设及 V5。R3 的三项合取逐项判断，不把任一未知当命中或通过；盈利对冲按原文证据门槛判定。适用的 R14 油价压力情景、R20 内需情景不能因无法精确量化而默认为通过。
- **Terminal §8**：A 股与港股固定参数、四步推导、可达性和预期差。负 PE 的隐含倍数不用于正常盈利可达性判断。TAM、份额和稳态利润率先研究同口径区间，不因没有“官方稳态预测”就全部交回用户；公开事实不足以支持假设时明确保留缺口。
- **Price Map §9**：逐项核对强制映射，包括 R1/R3/R5/R6/R9/R14/R17/R18/R19/R20 和 D5 状态。R9 缺项或 D5 承接暂停等限制买入资格时，Gate 允许继续估值的标的仍须计算跟踪/观察价位；取消 P2 单独标状态和理由。

## 4. 估值参数与数值交付

计算前必读 [估值与轻量输出契约](references/valuation-and-output.md)。关键约定：

- canonical 已有数值必须沿用；未规定绝对档位的 `d_base/r_k` 是本次分析假设。研究者给证据、取值理由、区间/敏感性与风险去重说明，再选基准值。不得称其为框架默认值，也不创建通用折扣表替代 canonical。
- 最终价格统一为交易币种/股。总市值与每股价值分开输入；EV 先明确扣净债务及其它权益调整。汇率写清方向，股份数用实际股数。
- `P2=P1_low×(1-step_down)`，不能改用 P1 中值；未舍入值参与计算，最后舍入。冻结/否决/真正不可估状态不给新的 P1/P2；旧参考值只在报告解释，不伪装为本期有效价位。
- 使用 `scripts/stock_price_map.py build` 从 scratch 计算输入生成轻量 JSON；依据计算结果渲染报告。临时模型输入不是额外最终交付，完整假设与算式必须留在报告。
- T1/T2 保留框架规定的价格条件及事件条件，不任意发明固定涨幅目标。账户参数缺失时报告给 cap 公式与缺项；不降级整个价格地图，不在 JSON 存仓位分配。

## 5. 监控、验收与保存

- 监控最多 10 项，优先最脆弱估值假设、现金流/筹码、适用的 R3 宏观约束和最近重要窗口；能改变价格区间的变量也应入选，不仅是能改评级的变量。适用项覆盖优先，不凑数。
- 每项有当前事实及日期（缺失为 null）、可观测触发判据、具体动作、来源和下次检查事件/日期。事实基线来自同一底稿；定性判据可用，但不能只有“关注”。区分框架阈值与本次分析阈值；假设与当前事实分开写在报告。
- 节省开销不通过缩减适用问题、硬截断证据字数、减少关键事实独立核验或跳过敏感性来实现。主代理核对完整框架覆盖及跨主题依赖；研究深度按未决风险扩大。
- 人工语义验收：关键证据冲突已裁决或明确影响；报告九节与 DCS 完整；币种/股本/现金桥/Terminal 算术正确；风险没有重复扣减；报告与 JSON 的 V50/P1/P2/T1/T2/监控基线一致；非买入价位不含执行许可。
- 运行 `python3 scripts/stock_price_map.py check <JSON>`。它只验证结构和状态；不能宣称已验证来源真实性、估值合理性或报告全文一致性。
- 最终文件：`research/investment/companies/<市场>-<代码>/<日期>/investment-<代码>-<日期>-research.md`、`research/investment/companies/<市场>-<代码>/<日期>/investment-<代码>-<日期>-price-map.json`。验证完成后首个正式运行刷新 `output/indexes/investment/<市场>-<代码>/investment-<代码>-latest.json` 为日期 JSON 的完全相同副本；`meta.report_path` 始终指向对应报告。
- 同日已有产物先核对报告 §0 的输入/框架指纹与证据截止。完全匹配且未要求复评可复用；其它情况自动选择未使用的 `-r2/-r3…` 同后缀报告和 JSON，隔离运行不刷新 latest。只有用户明确授权才覆写原文件或提升隔离版；不能因旧指纹缺失假定输入相同。
- 报告 §0 记录运行模式、数据/证据日期、框架版本及 SHA-256、已提供数据包指纹、隔离/复评来源、沿用/更新范围及依据；关键原始来源和页码/章节直接保留在报告，不能只引用被忽略的 scratch 目录。
- 回执给用途状态、P1 区间、P2 或取消原因、关键监控和报告/JSON 路径。未能形成估值时说清具体阻断输入、已尝试的补证及解除条件，不把全 null 包称为成功价格地图。
