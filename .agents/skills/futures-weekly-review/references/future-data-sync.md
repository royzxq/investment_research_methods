# 期货工具同步

用于方法适配后的必要联动、已授权 direct 维护，或证据纠错中修复与现行定义不一致的实现。同一更新分支处理，不另开 PR；单阶段不自动研究、适配、重评或发布。

## 输入与判断

- 输入 AS_OF_DATE、实际 canonical、适配/maintenance/纠错报告及受影响脚本。先核报告和工作区版本一致；已有同步记录匹配则复用，输入变化另存差异。拟议报告不代替已完成修改。
- `future_data.py` 负责结构化行情与预检；字段/品种/取数适用范围变化才修改对应采集逻辑。**仅参数或阈值变化且输入字段不变，通常不改采集脚本；计算 helper 仍须按数值语义逐项核对。**
- 模型确认、计划与风险语义变化检查实际 helper 和调用方；`futures_risk.py` 是容量入口，不在周报另存公式。实现纠错按既定定义修复，可不变方法版本；改变定义则同时列 method_change。
- 不把天然人工产业数据强行自动化。T/V 与历史模型隔离，旧评分/系数不静默作用于新计划，旧影子引擎不冒充新版收益验证。

## 执行与交付

1. 列清采集脚本、模型/风险 helper、刷新/接续工具分别是否需改；无需改则给理由，不制造版本升级。
2. 必要时同步实际调用、字段和有意义的边界测试。仅 helper 改动不强行改 future_data.py；修改采集逻辑时更新其现有版本和适用说明。
3. 运行 py_compile 及适用离线测试，重点检查信号日排除、真实合约、原有效期、T 无 TP/净R、V 信号前冻结时序与配对绑定、原计划独立日历、未知账户和整数容量。接续改动另验跨 worktree 导入、按类型发现、文案兼容和真实计算依赖变化。API、账户与收益未验证就明确；不延用旧环境永远不可联网的断言。
4. 报告“8. 数据脚本同步”或纠错的实现同步段，记录 before→after、方法是否变化、旧输出失效项、测试和未验证范围；返回入口完成受影响诊断与 handoff，不另建审计口径。
5. 默认本地保存；已授权 publish 时按入口的日志/更新分支边界提交必要文件，不自行 push 或开 PR。不因无需改脚本而制造空提交。
