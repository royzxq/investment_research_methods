# 期货数据脚本同步（适配后的联动阶段）

用于 `update_needed=yes` 且适配已完成的新版框架及报告；或入口 `direct` 模式中已获授权、已完成设计修改并有 maintenance 实施记录的必要联动。在同一框架更新分支／worktree 处理，不新开分支或 PR。单阶段同步不自动扩成研究、适配、审计重评或精简；返回重评所需信息给入口。

## 输入与职责

- `AS_OF_DATE`、`NEW_FRAMEWORK`（工作区新版 `framework/futures_framework.md`）、`ADAPTION_REPORT`（weekly 适配报告；direct 时为同日 maintenance 实施报告）、`CURRENT_SCRIPT`（`scripts/future_data.py`，含版本及适用边界）。
- 先核适配报告日期、新版框架版本与实际修订是否匹配工作区 canonical；已有「8. 数据脚本同步」还须核对其中最终版本与实际脚本/helper。缺报告或不匹配时返回具体缺口，不用 change-decision 的拟议版本替代已完成适配，也不自动补跑适配。已完成且一致的同步按根同日约定复用；输入变化则先列差异，不静默覆盖原同步记录。
- `future_data.py` 负责结构化行情与预检，不因每周档位／参数变化自动改。现货基差、库存、产能性判决、SMM 等仍按现有适用边界处理，不把天然人工项强行脚本化。
- 涉及 canonical 的模型确认、计划风险、费用、系数或组合上限时，读取现行模型/风险 helper 及实际调用方；`scripts/futures_risk.py` 为容量计算入口，不在数据脚本／诊断模板另存风险公式。人工输入不足返回缺口，数值容量可算不等于 G1–G6 已通过。T / V 与历史 A–H 的字段和默认模式必须区分，旧评分或旧系数不能静默作用于新计划。

## 判断与变更

1. 对照适配报告「2. 受影响模块」及修改类型：
   - 改数据脚本：合约增删、结构化输入字段增删或过期、品种卡新增需程序化序列等，且属于脚本原适用范围。
   - 改模型或风险 helper：确认信号、数值／计划风险口径变化；未变口径不改 helper。
   - 不改：仅参数、阈值、升降权、判断前置变化，且没有结构化字段变化；人工来源检查即使变为量化门，也不自动归脚本。拿不准先按现有适用边界判断。
2. 数据脚本与风险 helper 均无需改时不动脚本，在适配报告追加「8. 数据脚本同步」，写明确结论及逐项理由。仅 helper 需改时只改 helper 及相关调用，不强行改 `future_data.py`，分别报告两者的变更状态。
3. 需要改时定位实际受影响模块，不按旧章节号漏掉新模型接口。沿用已有取数、降级及权限处理；需要的 helper、调用方和有意义的边界测试一起同步。影子引擎未支持 T / V 时明确历史模式和人工前瞻轨迹边界，不能复用旧 TP/评分假装自动验证新模型。
4. 对实际修改的数据脚本更新文件头框架／脚本版本、现有格式的 changelog 和适用边界；helper 单独变化不制造无关的数据脚本版本升级。保留诚实验证声明，以当前实际测试为准：分别列离线合成数据、语法、线上 API 路径／字段／权限验证；未运行不声称已验证，不沿用“本环境永远无法联网”的固定断言。
5. 对实际改动的数据脚本/helper运行 `python3 -m py_compile <对应文件>`，有错误先修复；模型、风险 helper 或计算路径改动时运行有关的校验／合成数据检查，重点核信号日排除、真实合约边界、T 无 TP/净R、V 经济锚与方向、未知账户及整数组容量。纯语法通过不证明真实 API 可用或策略收益有效。
6. 报告「8. 数据脚本同步」记结论、版本 before→after、对应框架变化、验证范围与限制；实际 API 未测时明确“未经线上实测”及待确认内容。

## 输出与提交

- 返回是否改脚本（yes/no）、摘要、最终版本、旧输出失效项及验证限制。完整流程入口按共享审计模板刷新本期诊断，本阶段不另建诊断口径。
- 默认本地保存；`publish` 已授权时在适配之后追加独立 commit：即使无需改脚本也提交同步报告，不能与适配提交合并。需要改时纳入 `future_data.py`、报告及实际修改的 helper／调用／相关校验。阶段本身不 push 或开 PR。
