# etf monthly review（月度编排器）

节奏：每月最后一周或月初跑一次；出快照与写卡只在本地（云端无 tushare 权限）。整条流水线的产物都在分支上，最后统一开 PR，不直接改 main。

## 输入

- `AS_OF_DATE`：缺省当天（北京时间）。
- `HOLDINGS`：用户本月的持仓市值与策略现金，写成 `scripts/etf_allocate.py` 说明里的 JSON。02800 按港币填 `value` + `currency`，在 `fx_to_cny` 里写快照 §7 的中间价及来源。没给就问，不要沿用旧数下单。
- `F`：本月入金；缺省取 `framework/etf_portfolio_params.json` 的 `new_money.monthly_amount_cny`（测算按 1 万）。**规则是比例**：报告先写各席位占本月买入的比例，再按 F 折金额。

## 本月要做哪几层（框架 A14）

| 层 | 月份 | 做什么 |
|---|---|---|
| 每月 | 每月 | 步骤 1–4、8–9 |
| 双月主题评审 | 1、3、5、7、9、11 | 步骤 5：调用 `etf-theme-review`（5、9、11 月全量，1、3、7 月 light） |
| 季度检查 | 3、6、9、12 | 步骤 6 |
| 半年复核 | 6、12 | 步骤 7 |
| 年度评估 | 12 | 步骤 7 |

## 步骤

### 0. 分支

`git checkout -b etf-monthly/<AS_OF_DATE>`（从 main）。

### 1. 快照（本地，约 5 分钟）

```
/Users/xinquanzhou/miniconda3/bin/python3 scripts/etf_data.py --pool-csv /Users/xinquanzhou/Workspace/ai_investment/investment_prediction.csv
```

产物：`research/etf-<日期>-data-snapshot.txt`（末行须有「快照完成」）。§0 有接口异常先重跑一次；仍失败的项记入本月报告的缺口清单，不猜数。

### 2. 持仓、现金与净值台账

- 持仓文件按工具代码给市值；没有现行卡认领的持仓要写 `slot`（首期主题卡出来之前就是这种情况），黄金自动列为单列管理。
- 在 `research/etf-nav-ledger.csv`（`date,value_cny,flow_cny`）追加本月末一行：策略账户总市值（不含黄金）与本月外部资金流（入金为正）。台账是业绩与回撤复核的唯一口径（A10、A13）。

### 3. 本月分配与检查

```
python3 scripts/etf_allocate.py --holdings <持仓.json> --new-money <F> --ledger research/etf-nav-ledger.csv
```

输出：各席位占本月买入的比例与折算金额（先留足主题待配现金，缺口超过可用资金按缺口比例，余额留现金）、模块区间、核心子项偏离、单主题 >15%、两套压力损失、回撤复核状态。
暂停接收新增资金的席位（卡上 `pause`、还没有目标的主题、回撤 −25% 起的全部主题）自动跳过。**这是建议清单，交易由用户确认。**

迁移（首期主题比较定出目标后）与季度再平衡：加 `--rebalance --keep core-hsi`，高于目标的席位卖到目标（02800 以港币在境外持有，不卖），所得与入金按缺口比例补其他席位。迁移按参数 `migration`：按实际账户把主题调到 30%，可分批，最迟在其后的第一次季度检查前完成。

### 4. 回撤复核（触发才做，A10）

- −20%：专项复核损失来源（市场 / 主题选择 / 集中度）。−25%：主题暂停新增，完成资金期限、整体敞口与逻辑检查后恢复。−30%：请用户重新批准风险预算，不批准就改战略比例。
- 14 天内完成；**固定仓定投照常**，不因复核停投。

### 5. 双月主题评审（奇数月）

调用 `etf-theme-review`。评审改了目标的，下个月的分配按新卡执行；本月是否按新目标买，由用户在确认行动表时一并决定。

### 6. 季度检查（3、6、9、12 月）

- 模块超出区间（45–55 / 15–25 / 25–35）：原则上调回目标附近，先用新增资金，不够再做存量交易，列入交易清单由用户确认。核心子项偏离超过 min(目标×25%, 5pp)：复核。
- 风险统计：港股合计（恒指 + 红利低波 + 恒生科技 + 港股创新药部分）、科创50 + 半导体、恒指 + 恒生科技、红利 ETF 与蓝筹个股、A/H 同公司合并；私募无法穿透标"未知"。
- 按 `research/etf-2026-09-19-pool-research.md` 的方法重算相关矩阵与聚类，簇有变化写进报告，必要时更新参数 `risk_overlaps`。

### 7. 半年复核（6、12 月）与年度评估（12 月）

- 半年：固定仓工具（费用、TD/TE、规模、A/C 份额、港股通税差）、指数规则、候选池（席位调整只在此时）、重叠、投入预算与实际承受能力；连续两次评审主题不足时讨论缩小主题模块。
- 年度：主动模块对比基准（A500 49 / 科创50 7 / 恒指 24 / 红利低波 20，相同资金流与口径）和"初始主题篮子"模拟账户；审查战略比例。结论追加到 `research/etf-scorecard.md`。
  运行 12–24 个月后仍看不到净价值，提议缩小主题模块。

### 8. 变化检测（决定要不要动框架）

只有五类情况允许改 `framework/etf_framework.md` 与参数文件，其余一律不改（市场叙事、行情涨跌、板块轮动都不是理由）：

1. 结构性事实变了：指数编制规则修订、基金清盘/合并/费率变更、税费与 QDII 额度变化、平台规则变化。
2. 口径错了：快照或计算器发现算法缺陷（修复写进本月报告，附修复前后数字）。
3. 记分证据：A13 的半年或年度评估结论。
4. 上期挂账的观察项到期：上月报告"预备观察项"逐条复核，不许静默丢弃。
5. 用户在半年或年度复核里改管理参数（写明日期与理由；择时类规则仍须验证报告）。

改框架后在变更记录里写明触发的是哪一类。

### 9. 校验、导出、提交

```
python3 scripts/validate_etf_card.py            # 全部卡零错误，含跨卡不变量
python3 scripts/validate_etf_card.py --export   # 更新 research/etf-cards/current.json
python3 -m unittest discover -s tests
```

提交：快照 + 新版卡 + current.json + 净值台账 + 本月报告 `research/etf-<日期>-monthly-review.md`（模板见下）。开 PR 到 main；合并后执行侧下一跑读到新卡。**不推送、不合并——由用户决定。**

### 本月报告模板

```markdown
# ETF 月度复评 <AS_OF_DATE>

## 1. 快照
- 文件、接口通/异常、缺口清单里与持仓相关的项

## 2. 持仓与净值
- 策略账户市值、现金、本月入金；单位净值与回撤（台账）

## 3. 本月分配
- etf_allocate.py 输出：各席位缺口、建议买入、留存现金；暂停的席位及原因

## 4. 检查
- 模块区间、核心子项偏离、单主题 >15%、两套压力损失；回撤复核状态

## 5. 本月叠加的层
- 双月主题评审（链接评审报告与行动表）/ 季度风险统计 / 半年复核 / 年度评估

## 6. 变化检测
- 五类触发逐条：命中/未命中；预备观察项（下月必复核）
```

## 与其他 skill 的关系

- `etf-theme-review`：双月主题评审；只在奇数月由本编排器调用，或用户单独调用。
- `etf-card-research`：写/重写单张卡；由主题评审或核心卡更新调用。
- 期货、个股两条轨道的周度流水线与本流水线互不干扰；需要当期宏观事实时读个股轨道最新的 `research/investment-*-market-research.md`。
