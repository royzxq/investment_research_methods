# framework condense（框架精简后处理）

## 定位（先读这一段再动手）

- 输入为 `CANONICAL_PATH`、`COMPACT_PATH` 及本次变更报告（如有）。canonical 保存完整有效框架，compact 是同一框架的精简表达；两者保持详略关系，不能通过删除策略、分析环节或执行要求制造精简。
- 只删除重复表达、修订簿记、已失效过程和被最新状态明确替代的旧叙述。必要的经济逻辑、证据口径、适用边界与有效当前状态保留；无法确认是否失效时先保留。
- compact 可供 AI 实际标的研究与执行导航；change-analysis/adaption 的方法判断、参数核对与歧义裁决仍以 canonical 为准。历史比较读取已有日期研究/变化报告，必要时查 git，不要求 canonical 保存所有历周过程。
- adaption 局部更新 canonical；本 skill 对照当期 canonical 全文与上一版 compact，只同步受影响条目，再核全文一致性。日期更新不要求重写无关规则，稳定编号不重编；若需要重排，仍逐条保持有效内容。
- 主文原位更新最新状态，不累加历代“本次更新”标记。修改记录留在日期报告与 git；报告链接完整框架，只展示受影响片段。规则与动态状态优先在原文件内分区，不新增碎片模块。

## 目标（六项同时满足）

1. 核心方法论不丢
2. 数字阈值和风控纪律不丢
3. 例外条件和证伪条件不丢
4. AI 执行顺序更明确
5. 减少规则冲突和上下文稀释
6. 当期行情更新时不需要重写整个框架——固定规则与动态配置物理分层，动态部分独立成段

不设最低压缩率、目标字数或硬体积上限。已较精简的文件可以只减少少量文字；保真与可维护性优先，行数可因分行而增加。

## 方法：决策链骨架 → 四轴拆分 → 三种消重手段

### 第一步：提炼决策链，作为 compact 的顶层骨架

通读 canonical，提炼这份框架隐含的"从拿到一个待判断标的，到给出最终执行动作"的链条，写成开篇「0. 决策链总览」。**从当前这份 canonical 自身提炼**（期货大致是路由→状态→策略映射→打分→门槛→交易计划→持仓管理；股票大致是数据契约→Precheck→机制归类→Gate→估值→Terminal→Price Map→结论），不要套用另一轨道的阶段名。之后每条规则标注自己属于链条哪一步。

### 第二步：四轴拆分——对 canonical 每个内容单元逐一归类

| 轴 | 处置 |
|---|---|
| **固定规则 vs 动态配置** | 长期稳定的判定条件/阈值/公式/映射 → 固定规则层；随每周调研变化的"本周值"（状态矩阵当期值、当前主导项、当期事件日历、当期 DO_NOT_OVERREACT）→ 动态配置层。两层物理独立成段，不交织——动态层单独可替换是目标6的落点 |
| **通用规则 vs 品种特例** | 全标的适用的公式/规则 → 通用层；某合约/股票专属的否决、参数覆盖、验证输入 → 特例层，**只写与通用规则的差异（delta）**，通用部分不重复 |
| **执行条件 vs 背景解释** | 判断时要读的判据（条件、阈值、动作、例外）是 compact 的主体；"为什么这样设计"、论证过程、市场叙述**默认不进 compact**——canonical 是它们的家。唯一例外：某句背景是执行判据所必需（如换算基准、口径定义）时压成一行保留 |
| **当前结论 vs 历史过程** | 当期有效的结论/参数保留观测日期、证据限制及解除条件；纯历史演变、被替换的旧值、勘误过程、历代标记移出框架，历史由 git 与日期研究/适配报告保存。旧日期若仍是比较基准、连续条件或触发窗口则保留 |

分层在当前文件内完成，使用短引用连接权威定义，避免每周在多个位置重复改同一状态。

### 第三步：三种消重手段

1. **唯一出处（R-ID）**：任何规则/阈值全文只在权威位置出现一次并赋稳定编号（R1、R2…），其余处 `[Rn]` 引用。判据：改一处需同步改别处 → 即为副本，抽取。**跨周编号连续性**：再生成时先读上一版 compact，未变规则沿用原编号、新规则续号、永不重编
2. **条件化表达**：叙述性条文改写为"条件 → 动作"式紧凑判据。原文"若出现X情形，考虑到……（三行论证），应当把系数降至0.5并优先对冲" → `X → 系数×0.5，优先对冲`
3. **结构化字段**：同类规则统一成字段化条目或表格。推荐条目格式（按内容自行调整字段）：
   `Rn [链条步骤] 触发: … | 动作: … | 例外/豁免: … | 证伪/解除: … [源: canonical定位]`

## 保真模型：语义原子逐项保真（取代旧版"措辞逐字保留"）

允许改写措辞、允许压缩句式、允许彻底重排结构——**不允许丢失或走样任何语义原子**。每条规则的语义原子五元组：

**（触发条件，数值阈值，动作，例外/豁免，证伪/解除条件）**

- 数值阈值必须逐字：数字、单位、比较方向（≥/>/≤）一个都不许改写、近似或丢失
- 触发条件与动作可以换说法，但逻辑关系（且/或/非、顺序、优先级）必须精确等价
- 例外与证伪条件是最容易在压缩中丢掉的部分，**单独清点**
- 带复活/解锁条件的"归档/冻结/挂起"内容是活逻辑：条目本身可条件化改写，触发条件完整保留
- 本精简步骤只维护 compact；canonical 的规则变更交回 adaption，除非用户同时授权治理 canonical。发现原有歧义时只按明确的权威定义或优先级修正指代；没有依据的不静默裁定，也不编造缺失参数。

## 可追溯性

保留既有稳定规则标识与章节映射；来源在定义处或同组表头标明即可，不在每个重复引用后再附一份。来源指向现行 canonical 章节，不以 git 中被删出的有效规则补齐 compact。

## 强制自审清单（生成后逐项核对，不过不许提交）

1. **有效内容覆盖（首要）**：逐条核对条件、阈值、动作、例外与解除条件；检查完整方法、策略、评分、风控及输出契约是否仍有承载。发现遗漏就补回；数量/编号一致不能代替内容一致，未完整计数不得声称“100%语义等价”
2. **数值与公式核对**：用 `rg` 或只读脚本对照数值、单位、比较符、公式与当前日期；逐项解释删除项属于重复值或失效历史的依据。旧日期仍参与有效判据时不得删除；相同数字出现并不代表其逻辑角色未变
3. **R-ID 引用完整性**：无悬空引用、无重复定义
4. **自包含执行抽检**：选取 3 条已有明确完整定义的规则，构造假想情形，仅凭 compact 走一遍判断；因精简遗漏导致回查时补全。canonical 原有歧义/缺定义按第5项记录，不为自包含而编造规则
5. **副本矛盾检测**：不静默择一；有明确权威定义或覆盖关系时据此收敛并记录依据，否则保留原有边界、在报告列出待澄清项，不借精简修改方法
6. **决策链自检**：「0. 决策链总览」每一步在正文都有对应的固定规则与（如适用）动态配置，无断链、无空节
7. **体积与范围记录**：报告行数/字符或 UTF-8 字节 before→after，注明计量口径；确认未引入额外方法模块、研究范围限制或新的必办门。期货侧运行 `python3 scripts/futures_framework_governance.py --check`，股票侧核 R/D 编号、来源与章节引用；结构检查不能证明语义等价

## 输出与提交

1. compact 文件头简述与 canonical 的关系，注明方法/状态日期；只保留当前元信息，不积累每次精简的履历
2. 自审清单结果（覆盖核对、尺寸统计、歧义发现及验证限制）作为「精简版同步」小节写入本次 adaption-report（期货「9.」，股票「8.」），不粘贴框架全文
3. 在当前框架更新分支上 `git add` compact 与 report，追加独立 commit
4. 返回值：尺寸统计 + 保真核对结果与限制 +（如有）原有歧义，供编排器写进 PR 正文

上述提交动作适用于正在执行的框架更新流水线。单独调用时按用户已授权范围处理；需要发布框架改动时走分支与 PR，不直接改 main。仅要求本地整理时保留本地结果，不自动运行调研、提交或发布。
