# framework condense（框架精简后处理）

## 定位（先读这一段再动手）

- **compact 不是"canonical 的缩写版"，是一次重构**：canonical 是研究过程记录型文档（论证、演变、当期叙述交织）；compact 是从中提炼的、**给 AI 投研分析当指导框架用的规则系统**——执行 AI 拿到一个待判断标的，按它就能走完判断，不需要回看 canonical。
- **内容取舍的唯一判据**：一段内容如果不会在任何情形下改变执行 AI 的判断结果，就没有资格留在 compact 里。阅读舒适性文字、面向人的解释与铺垫、历史过程、与判断无关的市场叙述，一律删除——不是"压缩它们"，是整段不进。
- **本流水线自身的 AI 环节（change-analysis / adaption）永远只读 canonical，不读 compact**。change-analysis 的反摇摆判断恰恰依赖 canonical 保留的历史脉络；compact 为了可执行性会主动剥离这些，两者服务不同消费者，谁也不能替代谁。
- canonical 依旧由 adaption 逐次全文重写（本 skill 不改 adaption）；compact 每次从当期 canonical **无状态全量再生成**，不做增量修补。

## 目标（六项同时满足）

1. 核心方法论不丢
2. 数字阈值和风控纪律不丢
3. 例外条件和证伪条件不丢
4. AI 执行顺序更明确
5. 减少规则冲突和上下文稀释
6. 当期行情更新时不需要重写整个框架——固定规则与动态配置物理分层，动态部分独立成段

压缩率不是首要目标——但**个位数压缩率就是失败**：那说明只做了删标记，没做结构转换。canonical 的主要体积在叙述性表达与背景论证里，正确执行本方法后典型收益量级是字符 30–60%。

## 方法：决策链骨架 → 四轴拆分 → 三种消重手段

### 第一步：提炼决策链，作为 compact 的顶层骨架

通读 canonical，提炼这份框架隐含的"从拿到一个待判断标的，到给出最终执行动作"的链条，写成开篇「0. 决策链总览」。**从当前这份 canonical 自身提炼**（期货大致是路由→状态→策略映射→打分→门槛→交易计划→持仓管理；股票大致是数据契约→Precheck→机制归类→Gate→估值→Terminal→Price Map→结论），不要套用另一轨道的阶段名。之后每条规则标注自己属于链条哪一步。

### 第二步：四轴拆分——对 canonical 每个内容单元逐一归类

| 轴 | 处置 |
|---|---|
| **固定规则 vs 动态配置** | 长期稳定的判定条件/阈值/公式/映射 → 固定规则层；随每周调研变化的"本周值"（状态矩阵当期值、当前主导项、当期事件日历、当期 DO_NOT_OVERREACT）→ 动态配置层。两层物理独立成段，不交织——动态层单独可替换是目标6的落点 |
| **通用规则 vs 品种特例** | 全标的适用的公式/规则 → 通用层；某合约/股票专属的否决、参数覆盖、验证输入 → 特例层，**只写与通用规则的差异（delta）**，通用部分不重复 |
| **执行条件 vs 背景解释** | 判断时要读的判据（条件、阈值、动作、例外）是 compact 的主体；"为什么这样设计"、论证过程、市场叙述**默认不进 compact**——canonical 是它们的家。唯一例外：某句背景是执行判据所必需（如换算基准、口径定义）时压成一行保留 |
| **当前结论 vs 历史过程** | 当期有效的结论/参数保留；历史演变、被替换的旧值、勘误过程、历代标记一律不进 compact——git 与 canonical 是历史的 SSoT |

**后两轴是压缩率的主要来源**（背景与历史通常占 canonical 体积的三至五成），前两轴是可执行性与"更新不重写"的来源。

### 第三步：三种消重手段

1. **唯一出处（R-ID）**：任何规则/阈值全文只在权威位置出现一次并赋稳定编号（R1、R2…），其余处 `[Rn]` 引用。判据：改一处需同步改别处 → 即为副本，抽取。**跨周编号连续性**：再生成时先读上一版 compact，未变规则沿用原编号、新规则续号、永不重编
2. **条件化表达**：叙述性条文改写为"条件 → 动作"式紧凑判据。原文"若出现X情形，考虑到……（三行论证），应当把系数降至0.5并优先对冲" → `X → 系数×0.5，优先对冲`
3. **结构化字段**：同类规则统一成字段化条目或表格。推荐条目格式（按内容自行调整字段）：
   `Rn [链条步骤] 触发: … | 动作: … | 例外/豁免: … | 证伪/解除: … [源: canonical定位]`

## 保真模型：语义原子逐项保真（取代旧版"措辞逐字保留"）

允许改写措辞、允许压缩句式、允许彻底重排结构——**不允许丢失或走样任何语义原子**。每条规则的语义原子五元组：

**（触发条件，数值阈值，动作，例外/豁免，证伪/解除条件）**

- 数值阈值必须逐字：数字、单位、比较方向（≥/>/≤）一个都不许改写、近似或丢失
- 触发条件与动作可以换说法，但逻辑关系（且/或/非、顺序、优先级）必须精确等价
- 例外与证伪条件是最容易在压缩中丢掉的部分，**单独清点**
- 带复活/解锁条件的"归档/冻结/挂起"内容是活逻辑：条目本身可条件化改写，触发条件完整保留
- canonical 永远不动

## 可追溯性

每条固定规则（R-ID 定义处）、每条品种特例、每条动态配置项，标注 `[源: canonical 原始定位]`（如 `0.3#17`、`1.5 SI品种卡`）。背景性内容不进 compact，无需溯源。

## 强制自审清单（生成后逐项核对，不过不许提交）

1. **语义原子覆盖率（首要）**：通读 canonical，列出全部原子清单——每条否决/硬止损条款、每个数值阈值、每条品种专属规则、每条例外/豁免、每条证伪/复活条件——逐条确认在 compact 中有承载条目。给出总数与命中数，**未 100% 不许提交**，缺失返工
2. **数值 token 核对**：grep 抽取 canonical 全部数值 token（百分比/乘数/阈值/日期），逐一确认存在于 compact；仅存在于历史簿记/背景叙述中的数值除外（逐个说明豁免理由）
3. **R-ID 引用完整性**：无悬空引用、无重复定义
4. **自包含执行抽检**：随机取 3 条规则，构造假想情形，仅凭 compact 走一遍判断——若任何一步需要回看 canonical 才能执行，该处重写
5. **副本矛盾检测**：收敛副本时若发现文本互相矛盾——这是 canonical 已漂移的证据，不许静默择一：按权威位置版本收敛，矛盾原文记入报告提请人工修 canonical
6. **决策链自检**：「0. 决策链总览」每一步在正文都有对应的固定规则与（如适用）动态配置，无断链、无空节
7. **压缩率校准**：行数/字符 before→after。**低于 30% 时必须逐类说明剩余体积构成**（哪些部分为什么删不动、改不了），论证成立才许提交——不许静默交差

## 输出与提交

1. compact 文件头 HTML 注释：`<!-- 衍生规则系统（面向人与未来下游执行方，非本流水线 AI 环节输入）：由 framework-condense 自 <CANONICAL_PATH> vX.Y 于 <日期> 按决策链骨架重构；勿手改；流水线的 change-analysis/adaption 一律使用 canonical -->`
2. 自审清单结果（原子覆盖率、压缩统计、副本矛盾发现）作为「精简版同步」小节追加到本次 adaption-report（期货「9.」，股票「8.」）
3. 在当前框架更新分支上 `git add` compact 与 report，追加独立 commit
4. 返回值：压缩统计 + 原子覆盖率一句话 +（如有）副本矛盾提醒，供编排器写进 PR 正文

单独手动调用（无进行中的框架更新分支）时：新建 `compact-rebuild/<日期>` 分支提交并开 PR（compact 的任何改动一律走 PR，与 routine 纪律一致），自审照做，副本矛盾写进 PR 正文。
