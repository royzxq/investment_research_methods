# 自动深度调研（多代理编排）

给定一个调研问题，组织多个调研子代理并行取证，最后综合成一份可溯源、可复查的报告。本技能是本地实现（与官方手动版 `deep-research` 能力对齐、互不影响）；被其它技能调用时按调用方契约执行。

## 边界

- 需要能派生子代理（Agent 工具）；没有时退化为直接检索并在交付中声明降级。
- 检索路由：优先环境可用的 `gemini_web_search` MCP；不可用或失败（`[SEARCH_FAILED]`/`[gemini_web_search]` 标记）时回退内置 WebSearch/WebFetch。检索摘要只用于发现资料，关键事实必须打开原始来源核验并记录日期。
- 不修改调用方未授权的文件；默认不 commit/push。
- 不编造引用；拿不到证据就写「未找到/证据不足」。

## 输入（由用户或调用方给出）

- 调研问题（必填）；
- 约束：信息截止时间、地域/语言、来源等级要求（默认：截止=当天、中文优先、一手来源优先）；
- 输出契约（调用方指定时从其约定）：`OUTPUT_DIR`（默认当前工作目录）、报告路径与格式（默认叙述性报告；调用方可要求结构化证据条目）、子代理数量约定。
- 关键信息缺失且影响执行 → 先用 AskUserQuestion 问一次；否则按默认执行并声明所用默认值。

## 流程

### 1 标题与目录

取一个 3–6 词的短标题（无标点、不超过 50 字符，用户语言），创建：
`OUTPUT_DIR/research_notes/<标题>/` 与 `OUTPUT_DIR/reports/`。
标题用于笔记目录与报告文件名 `<标题>.md`；不得与既有目录重名（重名时加序号）。

### 2 拆解（MECE）

把调研问题拆成 3–6 个互相独立、合起来覆盖问题的子主题。粒度参考：聚焦主题 3 个（不同角度）；多维度评价 4 个；多实体/区域 5 个；大集合 6 个。宁可 4 个扎实，不凑 8 个浅的。每个子主题写成一条精确的检索任务。

### 3 并行派生调研子代理

在**一条消息内**并行发出全部 Agent 调用（subagent_type=general-purpose），每个子代理的提示词必须包含：

```
调研 {子主题}。
目标：{期望产出，覆盖哪些内容}
关键问题：
- {问题 1}
- {问题 2}
建议来源类型：{一手来源/监管披露/公司公告/行业数据/权威媒体……}
约束：
- 信息截止 {日期}；只采该日及之前的公开证据
- 每条结论附 [出处, 日期]；关键事实打开原文核验，禁止只引检索摘要
- 必须给出「未找到/证据不足」结论与反向/对称证据
- 不给出未经要求的建议或预测
输出：结构化证据条目（主题｜结论｜证据｜出处｜日期｜强度｜影响方向），写入 {绝对路径}/research_notes/{标题}/{子主题}.md
```

各子主题的检索面不得互相重复；发现重叠立即调整。

### 4 补研（最多一轮）

汇总各子代理返回后，仅当存在会使报告结论不成立的**关键缺口**时，补派生 1–2 个子代理（同第 3 步格式）。**只允许一轮**；完成后直接进入第 5 步。

### 5 综述

派生一个综述子代理：读取 `research_notes/<标题>/` 全部笔记，整合为报告写到 `OUTPUT_DIR/reports/<标题>.md`。要求：

- 完整回答调研问题；调用方指定格式时（如结构化证据条目）从其格式；
- 关键结论逐条带出处与日期；显式列出证据不足项、互相矛盾的证据与未决问题；
- 区分「已核验事实」与「推断」；不虚报确定性。

### 6 交付

返回：报告路径 + 3–5 句摘要 + 缺口清单（未取得项）。对话直用场景（无文件需求）直接给摘要。

## 质量与成本纪律

- 每条结论可溯源；禁止编造引文与来源。
- 子代理总数默认 3–5 个研究 + 最多一轮补研（+1–2）+ 1 个综述；调用方另有约定从其约定。
- 子代理失败时：主代理直接完成该子主题，或在交付中记为缺口——不得假装完成。
- 笔记与报告必须落盘、可复查；不落盘即视为未完成。
