# ADR-20261008：自动个股研究最少间隔七天

状态：已接受（用户2026-10-08授权实施）。

## 问题

每日四只与事件去重不能限制同一上市证券的新批次、新证据或重启后重复研究。旧 runner 在启动 CLI 前写 process.started_at；仅凭这个字段或 reservation 不能证明实际启动，长时间预检/锁等待还会让按该时间计算的七天间隔提前。

## 裁决

所有自动触发来源共享上市证券 task_id 冷却期，从同轮首次实际启动至下一轮首次启动至少 7×24 小时。A/H 是不同上市证券。优先剔除冷却中的证券，再按现有四档及首次等待时间选每日最多四只；延期保持 pending，次日须有当日新输入，不使用过期估值包。单次晨检先释放前日确认未启动的active预留，再合并新包；只对合并后的最终队列写冷却日志，避免空过当天或重复记录。新 event_key、批次、来源与服务重启不能解除冷却。

Codex 与 Claude 同轮合用一次证券名额和最早启动时刻。已启动后失败、超时或取消仍计数；同批次、同请求指纹的在途恢复及缺失端补完可继续，不把第二端启动时间推成新一轮。纯预检失败、确认未启动的预留可释放。持有 claim 但缺少进程证据的歧义状态保守保留，不能声称从未启动。

research-queue/v1 增加可选迁移字段 last_started，按 task_id 保存 started_at、batch_id、request_sha256。读取旧台账只补充该字段，不重置 entries、days 或 completed_events。每次计划/执行从不可变 runner request、claim 与 process/entry 校验身份、指纹和时间后重建；process.pid>0 才证明 Popen 启动，pid=null 且 failed 证明启动前失败。新runner在Popen成功返回后更新process和entry的started_at，并在process保存相同launched_at标记，使用这个略晚于实际进程启动的保守时刻精确计算168小时。旧记录缺少该标记时，以completed_at保守代替启动时间；旧的last_started缓存同步向后纠正，不能用min保留更早的预检时间。旧在途/歧义记录没有completed_at时以当前检查时间保持冷却，恢复同轮仍可继续；明确PID启动证据优先于歧义claim。进程记录缺失而仅剩entry时同样使用completed_at，避免把旧预检时间当实际启动。旧一批可能延长等待，不提前准入。双端取同轮最早可信时刻、跨轮取最近一轮；启动证据保留在 runner 目录，崩溃后仍可重建。坏格式或指纹不符拒绝运行。

plan 只在内存迁移并输出 cooldown_skipped 的 next_eligible_at；run 原子保存历史，统一日志逐只写 cooldown_skipped。已有每日额度原样保留，不因迁移返还实际启动额度。必须连同 queue 和原 runner 输出备份，删除两处历史无法恢复真实启动事实。

## 验证与范围

离线回归覆盖精确168小时边界、来源/新事件/新批次、防重启绕过、双端最早启动、真实启动失败、未启动预检释放、同轮恢复、冷却后补位、A/H 分立、旧台账迁移与损坏拒绝。

修改methods调度器、runner启动时间证据与对应测试/说明，不改服务排期或AI写回。手工 runner 不成为自动调度入口；其现行规范批次中的真实启动也进入自动冷却历史。本裁决不执行或许可证券交易。
