# ADR：研究财务定义与监控交付质量

日期：2026-10-31。状态：用户已授权实施。

## 问题

切换前后研究复盘发现：调整后利润的定义可能与引用财报相反；监控可能将恶化触发和关闭告警混写；来源为分号、检索词为占位文字也能通过旧交付检查。现有算术审计和来源字段非空检查不能解决这些问题。

同时，历史研究的价格预测优势尚未得到证明。这次修改不能推导新的投资阈值、统一估值倍数、分歧熔断线或模型权重。

## 决策与边界

- 实际研究入口继续是共享的 `stock-research` 和 `deep-research-auto`。财务原文定义、调节表、研究调整及预测假设在既有底稿/报告中区分；遇到关键定义或触发方向冲突时做独立原文核验，无独立能力时披露主代理复查方式。不开设第二套评分体系。
- 估值差异在本端独立估值完成后，按期间、利润、现金债务、股本汇率、方法/倍数与折扣解释；没有对端材料时不等待、不假称已比较。合理假设可以不同，不自动平均、收敛或改权重。
- 监控明确当前是否满足判据、下一观察期、触发动作和解除条件。补证任务不冒充日常公开指标；仍保留所有有效控制，摘要删除不等于解除。
- 新准备批次冻结 `two-price-controls/v5`，价格 JSON 仍为 `stock-research/v4`、计算审计仍为 `stock-research-audit/v2`，不增加最终 JSON 字段。v5 在原 v4 公开监控要求上增加质量检查；v4 及更早冻结提示词字节和原验收行为不变。
- `validate_monitoring_delivery(..., quality=True)` 拦截来源/检索词的纯标点、纯数字、全字段占位，以及 NFKC/大小写/空白规范化后重复的变量。只检查这些确定性反例，不用自然语言正则猜测财务定义、告警方向或经济同义关系，不强制指标条数凑满。
- `research_runner.validate_delivery_monitoring` 按冻结合同选门禁，供正常发布、方法隔离后发布、恢复终态验收和原产物恢复发布共用。手动新研究显式运行 `stock_price_map.py check --require-monitoring-quality`；普通历史 check 和 build 不追补新门禁，旧冻结批次仍可使用原 writer。

## 失败与兼容

新批次质量不合格时沿用原输出失败/有限重试机制，不发布坏产物、不替研究者改价。恢复验收不能因为原回执曾成功就略过本合同的检查。旧合同的弱字段可继续按原约定恢复；这不等于它们达到新质量标准，也不修改历史内容。

投资方法、canonical/compact、调度和真实模型配置均未改变；不改 ai_investment 的 CSV、模型权重或数据 schema。CLI 启动适配器 `research_harness.py` 无需改动：质量要求在所有生成端共享的 runner 提示词及验收层执行。

## 验证

回归覆盖：无效 source/public_search、排版重复、不同期间不误合并、尚未披露与空摘要合法、手动检查不改文件、正常发布拒绝、恢复发布拒绝、旧 v4 提示词 SHA-256 与旧验证行为保留；现有运行器、恢复、DSH 及合同测试继续执行。原文语义另外用留存财报与监控样例前向复核，不能将结构测试通过宣称为研究准确性提升。

## 回退

如需停止为未来新批次启用 v5，将默认选择恢复为 `PUBLIC_MONITORING_CONTRACT`，保留已冻结 v5 的识别、提示词和验收分支，避免在途批次无法恢复。不得通过把 v5 重新标成 v4 来降低已冻结要求；不回写旧研究或解除任何投资控制。
