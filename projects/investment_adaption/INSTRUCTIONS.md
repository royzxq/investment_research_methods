# 股票框架适配 — Project Instruction

## 定位与输入

阶段③根据 `{{FRAMEWORK_UPDATE_RESULT}}` 局部维护 `{{CURRENT_STOCK_RESEARCH_FRAMEWORK}}`；不是普通公司研究。输入必须包含三类变更判定、KEY_VARIABLE_CHANGES、UPDATE_FOCUS、DO_NOT_OVERREACT_ITEMS，以及已采纳方法来源。旧报告仅有 update_needed 时先阅读具体变更重新分类，不沿用旧字段推断类型。

默认本地，需修改 canonical 用分支/隔离 worktree；只有明确授权才交入口统一提交/发布 PR，不自动合并。单阶段适配不自行精简、推送或开 PR。状态/证据 handoff 与方法 PR 分开，入口负责接续。

## 六步适配

1. **确定修改范围**。state_refresh 用既有规则更新事实；evidence_correction 更正来源、时间或完成断言；method_change 改变权重、顺序、阈值、适用对象、动作、例外或解除条件。update_needed=no 仅表示无方法变更，不禁止状态/纠错。无正文必要改动时只交回 handoff 输入，不做无效版本升级。
2. **识别受影响模块与对象**。风险前置、终局假设、估值与压力情景、回归催化、筹码/拥挤、治理与资本、Price Map、买入资格、减仓/淘汰、待复评均按实际传导选择。临时买入限制不自动禁止证据充分的估值和观察价位，缺可靠输入仍不可估。
3. **先审方法，再编辑**。新规则需完整时点/单位/取价/等号/AND-OR/窗口/unknown/解除定义、经济理由、适用对象、正反及边界案例、兼容影响；说明预期减少什么误判、可能增加什么遗漏。定义不全就留 proposed，不写入有效方法，不靠删除 unknown 保护修复不可用路径。固定日历、全市场指标用于个股时说明为什么适用及怎样滚动解除。
4. **局部执行**。保持结构与 `{{COMPANY_NAME}}`、`{{TICKER_OR_CODE}}`、`{{VALUATION_DATE}}`；不重写无关有效规则。当前事实优先通过独立日期报告/handoff 提供。需同步原位 observation 块时仅写受限事实字段；混排 D 段仍参与方法指纹，不能把整段排除。历史放日期报告与 Git，不叠历代标记。
5. **验证与兼容**。保存旧/新两份正文哈希、method_fingerprint、变更分类；仅受限 observation 块变更才自动认为方法相同。其他正文差异需审查，可针对明确兼容澄清保存审查凭证；版本标签相同不证明兼容。边界案例和定向回归检验方法动作与退出可达，不只验证关键词。正文/compact 同步由完整入口完成。
6. **交付**。状态与纠错用已采纳旧方法继续采用，待审新方法不抢先生效。合并/明确采纳后新建 handoff 绑定实际方法来源并说明哪些公司判断要重评；不重写旧 handoff，也不让被撤回证据重新生效。

## 适配报告

保存到入口分配的本期 revision，标题「个股调研框架更新结果」：

1. **更新结论**：三类变更、正文是否修改、方法 proposed/adopted、主要原因。
2. **受影响模块**：位置、原因、变更分类、对象范围、修改摘要。
3. **修改说明**：旧问题、经济依据、具体定义、动作与例外、正反/边界案例、兼容及复评影响。
4. **不应过度反应**：明确保留的规则与不据此扩大的约束。
5. **新版框架链接**：指工作区 canonical，列必要变更片段，不粘全文。
6. **版本变更记录**：旧/新正文哈希和方法指纹、采纳来源/状态、已采用状态 handoff、待研究与完成凭证。
7. **验证**：实际运行的结构检查、失败路径/边界测试、未核验市场事实与未运行实盘/API；不得把结构检查写成方法有效性证明。
8. **精简版同步**：完整入口填写 compact 变更、保真限制与检查结果；单阶段标未执行，不扩任务。
